# دستورات خط فرمان (Artisan Commands)

در این بخش، دستورات اختصاصی xShop و کاربرد آن‌ها را معرفی می‌کنیم. این دستورات برای مدیریت دارایی‌های فرانت‌اند، توسعه قالب، تولید داده‌های آزمایشی، ایجاد کنترلر و مهاجرت اطلاعات استفاده می‌شوند.

## ۱. ساخت دارایی‌های فرانت‌اند (Assets Build)



```bash
php artisan build
```

این دستور فرایند ساخت دارایی‌های فرانت‌اند را اجرا می‌کند و در عمل دستور زیر را فراخوانی می‌کند:



```bash
npm run build
```

از این دستور زمانی استفاده کنید که امکان اجرای مستقیم دستورات npm از طریق SSH وجود ندارد و لازم است فرایند Build از طریق Artisan انجام شود.

پیش از اجرا، مطمئن شوید محیط اجرا دسترسی‌های لازم را دارد. اجرای Build در محیط Production معمولاً توصیه نمی‌شود؛ بهتر است دارایی‌ها در محیط توسعه یا فرایند استقرار آماده و سپس منتشر شوند.

## ۲. آماده‌سازی دارایی‌های کلاینت (Client Asset Generator)

```bash
php artisan client
```

این دستور تغییرات مربوط به دارایی‌های سمت کاربر را جمع‌آوری و آماده می‌کند. پیش از شروع کار با سامانه، باید حداقل یک بار اجرا شود.

پس از تغییرات در Theme نیز، در صورت نیاز، این دستور را پیش از اجرای فرایند Build اجرا کنید:



```bash
php artisan client
php artisan build
```

توصیه می‌شود این مراحل در محیط توسعه یا فرایند استقرار انجام شوند تا محیط طراحی از محیط عملیاتی جدا بماند. این توصیه به دلیل تفکیک مسئولیت‌هاست، نه لزوماً وجود مشکل امنیتی در خود دستورات.

## ۳. ساخت Theme Part



```bash
php artisan make:part {part} {segment}
```

این دستور فایل‌های موردنیاز برای ایجاد یک Theme Part جدید را در Segment انتخاب‌شده ایجاد می‌کند.

پیش از اجرا:

- محدوده و کاربرد Theme Part را مشخص کنید.
- Segment مناسب را با توجه به محل استفاده انتخاب کنید.
- از ایجاد بخش‌های تکراری خودداری کنید و در صورت وجود نمونه مشابه، امکان استفاده مجدد از آن را بررسی کنید.

فایل‌های ایجادشده عبارت‌اند از:

- `PartName.php`: تعریف متدهای `onAdd`، `onRemove` و `onMount`
- `PartName.blade.php`: ساختار HTML و کدهای Blade
- `PartName.scss`: استایل‌های بخش
- `PartName.js`: رفتارهای JavaScript
- `screenshot.webp`: پیش‌نمایش Theme Part

برای جزئیات بیشتر، به مستند ساخت Theme Part مراجعه کنید. [create-new-theme-part.md](create-new-theme-part.md)

## ۴. ساخت xController



```bash
php artisan make:xcontroller {model}
```

`xController` ابزار اصلی پروژه برای کاهش کدهای تکراری و ساده‌سازی پیاده‌سازی عملیات CRUD است.

با اجرای این دستور، کنترلر مربوط به مدل برای بخش مدیریت و دو فایل Blade مربوط به فهرست (`list`) و فرم (`form`) ایجاد می‌شوند.

برای آشنایی با امکانات و نحوه استفاده از آن، مستندات اختصاصی `xController` را مطالعه کنید. 
[x-controller.md](x-controller.md)

## ۵. تولید تصاویر آزمایشی برای مدل‌ها

### آماده‌سازی مجموعه تصاویر



```bash
php artisan seeding:prepare
```

این دستور مجموعه‌هایی از تصاویر آماده برای داده‌های آزمایشی را در مسیر زیر قرار می‌دهد:

text

```
database/seeders/images
```

### اختصاص تصاویر به مدل‌ها



```bash
php artisan seeding:image {model} {directory}
```

این دستور تصاویر یک پوشه مشخص را برای مدل موردنظر استفاده می‌کند؛ برای مثال، می‌توانید تصاویر آزمایشی محصولات را به مدل `Product` اختصاص دهید.

### تولید تصاویر برای همه مدل‌های پشتیبانی‌شده



```bash
php artisan seeding:all digital
```

این دستور از تصاویر موجود در پوشه مجموعه انتخاب‌شده، تصاویر تصادفی انتخاب می‌کند و به مدل‌های پشتیبانی‌شده اختصاص می‌دهد.

برای مثال، در این دستور مجموعه `digital` انتخاب شده است. مسیر مورد انتظار آن `database/seeders/images/digital` است.

> این دستورات برای داده‌های آزمایشی کاربرد دارند. پیش از اجرا، مدل‌ها و مسیر تصاویر را بررسی کنید و از اجرای ناخواسته آن‌ها روی داده‌های واقعی جلوگیری کنید.

## ۶. به‌روزرسانی تست‌های خودکار



```bash
php artisan test:update
```

این دستور برای به‌روزرسانی فایل تست نهایی سیستم استفاده می‌شود و بیشتر کاربرد توسعه‌ای دارد. برای مثال، پس از اضافه کردن Route جدید در پنل مدیریت، ممکن است برای هماهنگ‌سازی تست‌های خودکار به آن نیاز داشته باشید.

پس از به‌روزرسانی تست‌ها، آن‌ها را اجرا کنید:



```bash
php artisan test
```

توجه داشته باشید که تولید یا به‌روزرسانی فایل تست به‌تنهایی تضمین نمی‌کند که تمام رفتارهای جدید به‌درستی آزمایش شده‌اند؛ تست‌های مرتبط را نیز بررسی کنید.

## ۷. مهاجرت از وردپرس (xShift)



```bash
php artisan xshift {action} {url?}
```

این دستور برای انتقال اطلاعات از WordPress و WooCommerce به xShop استفاده می‌شود. پارامتر `action` نوع اطلاعات موردنظر برای مهاجرت و `url` آدرس وب‌سایت مبدأ را مشخص می‌کند.

برای مثال:



```bash
php artisan xshift group https://wp.example.com/
php artisan xshift post https://wp.example.com/
php artisan xshift category https://wp.example.com/
php artisan xshift product https://wp.example.com/
```

برای اجرای این دستورات، افزونه `xshift` باید روی وب‌سایت وردپرسی نصب و فعال باشد.


::: warning
 هشدار: دستور `xshift clear` اطلاعات محتوایی و محصولی را حذف می‌کند. پیش از استفاده، مستندات مهاجرت را مطالعه کنید و از اطلاعات موردنیاز نسخه پشتیبان تهیه کنید.
:::

برای مراحل کامل مهاجرت، پیش‌نیازها و محدودیت‌ها، به مستند مهاجرت از WordPress و WooCommerce به xShop مراجعه کنید.
