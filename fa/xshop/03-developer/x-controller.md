# مستندات xController

## xController چیست؟

`xController` یک کنترلر پایه و عمومی در xShop است که با هدف کاهش کدهای تکراری (Boilerplate) و ساده‌سازی پیاده‌سازی عملیات CRUD طراحی شده است. این ابزار بخش زیادی از ساختار اولیه کنترلرها، فرم‌ها و فهرست‌های پنل مدیریت را ایجاد می‌کند تا توسعه‌دهنده بتواند روی منطق اختصاصی هر مدل تمرکز کند.

> نکته: `xController` برای استفاده در پنل مدیریت طراحی شده است و هدف آن ساخت کنترلرهای عمومی برای بخش کاربری سایت نیست.

## ۱. ساخت xController

ابتدا مدل و Migration مربوط به آن را طبق روال معمول لاراول ایجاد و تکمیل کنید. پیش از اجرای دستور، ویژگی‌هایی مانند `SoftDeletes` و سایر نیازمندی‌های مدل را مشخص کنید؛ زیرا کدهای تولیدشده بر اساس ساختار موجود مدل ایجاد می‌شوند.

سپس اجرا کنید:



```bash
php artisan make:xcontroller {model}
```

برای مثال، اگر مدل شما `Category` است، دستور مربوطه را اجرا کنید:



```bash
php artisan make:xcontroller Category
```

این دستور فایل‌های زیر را ایجاد می‌کند:

- Controller: در مسیر `app/Http/Controllers/Admin/`
- Viewها: در مسیر `resources/views/admin/{model_name}`، شامل فایل‌های فهرست و فرم
- Save Request: در مسیر `app/Http/Requests/` برای تعریف قوانین اعتبارسنجی اطلاعات

پس از تولید فایل‌ها، کدهای ایجادشده را بررسی و متناسب با نیاز مدل خود تکمیل کنید.

## ۲. پیکربندی کنترلر

در ادامه، بخش‌های اصلی یک کنترلر مبتنی بر `xController` را بررسی می‌کنیم. مثال زیر از کنترلر دسته‌بندی‌ها گرفته شده است.



```php
class CategoryController extends XController
{
    protected $cols = ['name', 'subtitle', 'parent_id'];
    protected $extra_cols = ['id', 'slug', 'image'];
    protected $searchable = ['name', 'subtitle', 'description'];
    protected $with = ['parent'];

    protected $listView = 'admin.categories.category-list';
    protected $formView = 'admin.categories.category-form';

    protected $buttons = [
        'edit' => [
            'title' => 'Edit',
            'class' => 'btn-outline-primary',
            'icon' => 'ri-edit-2-line',
        ],
        'show' => [
            'title' => 'Detail',
            'class' => 'btn-outline-light',
            'icon' => 'ri-eye-line',
        ],
        'destroy' => [
            'title' => 'Remove',
            'class' => 'btn-outline-danger delete-confirm',
            'icon' => 'ri-close-line',
        ],
    ];

    public function __construct()
    {
        parent::__construct(
            Category::class,
            CategorySaveRequest::class
        );
    }
}
```

کاربرد ویژگی‌های اصلی:

| ویژگی | کاربرد |
| --- | --- |
| `$cols` | ستون‌هایی که در فهرست نمایش داده می‌شوند، به ترتیب تعریف‌شده |
| `$extra_cols` | فیلدهای اضافی موردنیاز سیستم که لزوماً در فهرست نمایش داده نمی‌شوند؛ مانند `slug` |
| `$searchable` | فیلدهایی که جست‌وجو در آن‌ها انجام می‌شود |
| `$with` | رابطه‌هایی از مدل که باید همراه رکوردها بارگذاری شوند؛ مانند `parent`، برای کاهش Queryهای اضافی |
| `$listView` | مسیر View فهرست |
| `$formView` | مسیر View فرم ایجاد و ویرایش |
| `$buttons` | تعریف دکمه‌های عملیاتی فهرست، مانند ویرایش، نمایش و حذف |

ویژگی‌های `$_MODEL_` و `$SAVE_REQUEST` نیز در بعضی کنترلرها به‌صورت کامنت دیده می‌شوند؛ در مثال بالا، مدل و Request از طریق سازنده به کلاس پایه معرفی شده‌اند.

## ۳. متدهای اصلی کنترلر

### `save()`

منطق ذخیره اطلاعات مدل را پیاده‌سازی می‌کند. مقداردهی فیلدها، تولید `slug`، ذخیره فایل و سایر عملیات اختصاصی مدل بر عهده توسعه‌دهنده است.

در پایان، معمولاً باید مدل ذخیره‌شده بازگردانده شود. به اعتبارسنجی ورودی‌ها در Save Request نیز توجه کنید.

### `create()` و `edit()`

این متدها فرم ایجاد و ویرایش را نمایش می‌دهند. در صورت نیاز می‌توانید داده‌های جانبی را نیز به View ارسال کنید؛ برای مثال، فهرست دسته‌بندی‌ها برای انتخاب دسته والد.

### `update()`

در مثال، با فراخوانی `bringUp()` عملیات به‌روزرسانی به سازوکار `XController` واگذار شده است. اگر به رفتار متفاوتی نیاز دارید، می‌توانید این متد را سفارشی کنید.

### `destroy()`

مسئول حذف رکورد است. در صورت وجود محدودیت‌های تجاری، مانند استفاده از یک دسته‌بندی در تنظیمات یا منو، ابتدا آن محدودیت‌ها را بررسی کنید و سپس عملیات حذف را انجام دهید.

### `bulk()`

برای اجرای عملیات گروهی روی چند رکورد استفاده می‌شود. در مثال، عملیات حذف و بازیابی رکوردهای حذف‌شده وجود دارد. برای افزودن عملیاتی مانند فعال‌سازی گروهی، باید هم گزینه مربوطه را به View اضافه کنید و هم منطق آن را در کنترلر پیاده‌سازی کنید.

### `restore()`

برای بازیابی رکوردهای حذف‌شده استفاده می‌شود و معمولاً در مدل‌هایی کاربرد دارد که از `SoftDeletes` پشتیبانی می‌کنند.

### متدهای سفارشی

متدهایی مانند `sort()` و `sortSave()` جزو منطق اختصاصی کنترلر مثال هستند و برای مرتب‌سازی رکوردها استفاده می‌شوند. این متدها الزاماً در همه کنترلرها وجود ندارند.

> برای شناخت بهتر رفتارهای پشتیبانی‌شده توسط `XController`، کنترلرهای موجود پروژه را بررسی کنید؛ به‌ویژه متدهایی که در کلاس پایه تعریف شده‌اند.

## ۴. ویرایش Save Request

فایل Save Request قوانین اعتبارسنجی ورودی‌ها را مشخص می‌کند. این قوانین را متناسب با مدل خود تکمیل کنید و مطمئن شوید که هم در ایجاد رکورد (`store`) و هم در ویرایش آن (`update`) درست عمل می‌کنند.

به‌خصوص برای فیلدهای یکتا، شناسه رکورد جاری، فایل‌ها و فیلدهای اختیاری، قوانین ایجاد و ویرایش ممکن است متفاوت باشند.

## ۵. سفارشی‌سازی Viewها

فایل‌های Blade تولیدشده نقطه شروع کار هستند و می‌توانید آن‌ها را متناسب با نیاز خود تغییر دهید.

### View فهرست

این View معمولاً از قالب عمومی فهرست پنل مدیریت استفاده می‌کند:



```php
@extends('admin.templates.panel-list-template')
```

بخش‌های مهم آن عبارت‌اند از:

- `list-title` و `title`: عنوان فهرست
- `filter`: فیلترهای اختصاصی
- `bulk`: گزینه‌های عملیات گروهی
- `list-foot`: محتوای اضافی پایین فهرست، مانند دکمه مرتب‌سازی

فیلترها و عملیات گروهی باید با سازوکار مورد انتظار `XController` هماهنگ باشند؛ صرفاً اضافه کردن یک فیلد یا گزینه به Blade، منطق سمت سرور آن را ایجاد نمی‌کند.

### View فرم

این View معمولاً از قالب عمومی فرم پنل مدیریت استفاده می‌کند:



```php
@extends('admin.templates.panel-form-template')
```

فرم را مطابق نیاز مدل خود توسعه دهید. به‌طور معمول دو بخش اصلی دارید:

- سایدبار: برای راهنما، نکات و اطلاعات جانبی
- فرم اصلی: برای فیلدهای ورود و ویرایش اطلاعات

مقادیر قبلی فرم را با `old()` و داده مدل پر کنید و نمایش خطاهای اعتبارسنجی را نیز در نظر بگیرید.

برای ساده‌تر کردن ساخت فرم‌ها می‌توانید از پروژه [Laravel Form Builder](<https://github.com/4xmen/laravel-form-builder>) استفاده کنید.

## ۶. قابلیت ترجمه خودکار

در مدل‌هایی که از قابلیت چندزبانه سیستم پشتیبانی می‌کنند، ممکن است دکمه ترجمه به‌صورت خودکار به فهرست عملیات اضافه شود؛ بنابراین نبودن آن در آرایه `$buttons` لزوماً به معنای غیرفعال بودن این قابلیت نیست.

## نکات پایانی

- پیش از تولید کنترلر، ساختار مدل و نیازمندی‌های آن را کامل کنید.
- اعتبارسنجی، مجوزهای دسترسی و محدودیت‌های حذف را متناسب با مدل بررسی کنید.
- برای سفارشی‌سازی، ابتدا نمونه‌های مشابه در پروژه را مطالعه کنید.
- برای درک دقیق رفتارهای عمومی، به پیاده‌سازی کلاس پایه `XController` مراجعه کنید؛ این مستند بر اساس نمونه `CategoryController` نوشته شده است.
