# Story

مدل `Story` برای مدیریت استوری‌های نمایشی، مشابه استوری‌های اینستاگرام، استفاده می‌شود. هر رکورد شامل عنوان، توضیحات، تصویر پیش‌نمایش، فایل اصلی، وضعیت انتشار و ترتیب نمایش استوری است.

## ساختار داده
| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه یکتای استوری |
| `title` | VARCHAR(255) | خیر | عنوان استوری؛ قابل ترجمه |
| `slug` | VARCHAR(255)، unique | خیر | شناسه متنی یکتای استوری برای استفاده در URL |
| `description` | LONGTEXT | خیر | توضیحات استوری |
| `image` | VARCHAR(255) | بله | نام یا شناسه فایل تصویر پیش‌نمایش استوری |
| `file` | VARCHAR(255) | بله | مسیر فایل اصلی استوری، شامل عکس یا ویدئو |
| `ext` | VARCHAR(255) | بله | پسوند فایل |
| `likes` | BIGINT UNSIGNED | خیر | تعداد لایک‌های استوری؛ مقدار پیش‌فرض `0` |
| `status` | TINYINT(1) | خیر | وضعیت انتشار؛ `0` برای پیش‌نویس (`Draft`) و `1` برای منتشرشده (`Published`) |
| `sort` | INT UNSIGNED | خیر | ترتیب نمایش استوری؛ مقدار پیش‌فرض `0` |
| `created_at` | TIMESTAMP | بله | زمان ایجاد استوری |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی استوری |
| `deleted_at` | TIMESTAMP | بله | زمان حذف نرم استوری |


## ویژگی‌ها

### `$translatable`

فیلد `title` به‌عنوان فیلد قابل ترجمه تعریف شده است و امکان ذخیره و نمایش عنوان استوری به زبان‌های مختلف را فراهم می‌کند.

## متدها

### `getRouteKeyName()`

فیلد `slug` را برای Route Model Binding به‌جای `id` استفاده می‌کند.

### `imgUrl()`

آدرس تصویر بهینه‌شده استوری را برمی‌گرداند؛ در صورت نبود تصویر، از لوگوی سایت به‌عنوان fallback استفاده می‌شود.

### `imgOriginalUrl()`

آدرس تصویر اصلی استوری را برمی‌گرداند؛ در صورت نبود تصویر، از لوگوی سایت به‌عنوان fallback استفاده می‌شود.

### `url()`

آدرس فایل اصلی استوری، شامل عکس یا ویدئو، را برمی‌گرداند؛ در صورت نبود فایل، از لوگوی سایت به‌عنوان fallback استفاده می‌شود.

### `commentCount()`

تعداد کامنت‌های استوری را برمی‌گرداند. این متد در حال حاضر پیاده‌سازی نشده و مقدار ثابت `15` را برمی‌گرداند.

## نکات

- فیلد `slug` دارای ایندکس یکتا است؛ بنابراین مقدار آن در جدول نمی‌تواند تکراری باشد.
- فیلد `image` برای تصویر پیش‌نمایش و فیلد `file` برای فایل اصلی استوری استفاده می‌شود.
- تصویر پیش‌نمایش بهینه‌شده در مسیر `optimized/stories/` و تصویر اصلی در مسیر `stories/` قرار دارد.
- مقدار `status` وضعیت پیش‌نویس یا انتشار استوری را مشخص می‌کند؛ نمایش استوری‌های منتشرشده به منطق برنامه وابسته است.
- فیلد `sort` برای تعیین ترتیب نمایش استوری‌ها استفاده می‌شود؛ ترتیب نهایی به نحوه مرتب‌سازی در کوئری‌ها وابسته است.
- فیلدهای `likes` و `sort` مقدار پیش‌فرض `0` دارند.
- فیلد `deleted_at` برای ثبت زمان حذف نرم در نظر گرفته شده است؛ فعال بودن قابلیت Soft Deletes به تنظیمات مدل وابسته است.
