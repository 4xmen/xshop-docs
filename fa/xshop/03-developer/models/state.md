# State

مدل `State` برای ذخیره‌ی اطلاعات استان‌ها استفاده می‌شود. هر رکورد شامل نام استان، مختصات جغرافیایی و نام کشور مربوط به آن است.

## ساختار داده
| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه یکتای استان |
| `name` | TEXT | خیر | نام استان؛ قابل ترجمه |
| `lat` | DOUBLE | خیر | عرض جغرافیایی استان |
| `lng` | DOUBLE | خیر | طول جغرافیایی استان |
| `country` | TEXT | خیر | نام کشور مربوط به استان؛ قابل ترجمه |
| `created_at` | TIMESTAMP | بله | زمان ایجاد رکورد |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی رکورد |
| `deleted_at` | TIMESTAMP | بله | زمان حذف نرم رکورد |

## روابط

- `cities()`: رابطه‌ی `hasMany` با مدل `City`؛ شهرهای مرتبط با این استان را برمی‌گرداند.

## ویژگی‌ها

### `$translatable`

فیلدهای `name` و `country` به‌عنوان فیلدهای قابل ترجمه تعریف شده‌اند.

این قابلیت امکان ذخیره و نمایش مقادیر متناسب با زبان انتخاب‌شده را فراهم می‌کند. برای مثال، نام یک استان می‌تواند در زبان فارسی «تهران» و در زبان انگلیسی `Tehran` باشد.

## متدها

### `cities()`

با استفاده از رابطه‌ی `hasMany`، شهرهای مرتبط با استان را از طریق مدل `City` دریافت می‌کند.

## نکات

- فیلدهای `lat` و `lng` مختصات جغرافیایی استان را نگهداری می‌کنند و برای بهبود تجربه‌ی کاربری در انتخاب موقعیت روی نقشه (Map Picker) قابل استفاده هستند.
- فیلد `country` نام کشور مربوط به استان را ذخیره می‌کند و برخلاف یک شناسه‌ی عددی، از نوع متنی (`TEXT`) است.
- فیلد `deleted_at` در ساختار جدول وجود دارد و برای ثبت زمان حذف نرم استفاده می‌شود؛ فعال بودن قابلیت Soft Deletes در مدل به تنظیمات آن وابسته است.
- در ساختار جدول، کلید خارجی یا ایندکس دیگری به‌جز کلید اصلی `id` تعریف نشده است.
