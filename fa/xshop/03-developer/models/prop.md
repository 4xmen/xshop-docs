# Prop

مدل `Prop` مسئول تعریف ویژگی‌های پویا و قابل تنظیم محصولات است. به‌جای تعریف ستون جداگانه برای هر مشخصه محصول، می‌توان ویژگی‌هایی مانند رنگ، ظرفیت، وزن، جنس، ضدآب بودن و موارد مشابه را تعریف کرد و از آن‌ها برای ثبت مشخصات، جست‌وجو، فیلتر و در صورت نیاز، تعیین قیمت و موجودی استفاده کرد.

ویژگی‌ها به دسته‌بندی‌ها متصل می‌شوند؛ بنابراین ویژگی‌های قابل ثبت برای یک محصول بر اساس دسته‌بندی آن تعیین می‌شوند. ارتباط `Prop` و `Category` از نوع چندبه‌چند است.

## جدول `props`

| فیلد | نوع | توضیحات |
|---|---|---|
| `id` | BIGINT UNSIGNED | شناسه ویژگی |
| `name` | VARCHAR(90)، یکتا | کلید فنی ویژگی؛ باید لاتین و بدون فاصله باشد، زیرا در بخش‌های مختلف برنامه به‌عنوان کلید آرایه استفاده می‌شود |
| `label` | TEXT | برچسب قابل نمایش ویژگی؛ قابل ترجمه |
| `width` | VARCHAR(300)، پیش‌فرض `col-md-6` | کلاس CSS برای تعیین عرض و نحوه نمایش ویژگی در رابط کاربری؛ به‌طور پیش‌فرض از کلاس‌های Bootstrap استفاده می‌شود |
| `required` | TINYINT(1)، پیش‌فرض 0 | مشخص می‌کند تکمیل این ویژگی هنگام ثبت محصول الزامی است یا خیر |
| `searchable` | TINYINT(1)، پیش‌فرض 1 | مشخص می‌کند ویژگی در قابلیت‌های جست‌وجو و فیلتر محصولات قابل استفاده باشد یا خیر |
| `type` | VARCHAR(60) | نوع داده و رفتار ورودی ویژگی |
| `unit` | TEXT، nullable | واحد اندازه‌گیری یا نمایش مقدار، مانند `gr` برای گرم یا `Gig` برای ظرفیت؛ قابل ترجمه |
| `sort` | INT UNSIGNED، nullable | ترتیب نمایش ویژگی‌ها |
| `options` | LONGTEXT، nullable | گزینه‌های مرتبط با نوع ویژگی؛ مانند فهرست رنگ‌ها یا گزینه‌های قابل انتخاب |
| `priceable` | TINYINT(1)، پیش‌فرض 0 | مشخص می‌کند مقدار این ویژگی در تعیین قیمت محصول مؤثر است یا خیر |
| `icon` | VARCHAR(128)، nullable | نام آیکون ویژگی از مجموعه Remix Icon |
| `created_at` | TIMESTAMP، nullable | زمان ایجاد |
| `updated_at` | TIMESTAMP، nullable | زمان آخرین ویرایش |
| `deleted_at` | TIMESTAMP، nullable | زمان حذف نرم ویژگی |

## انواع ویژگی‌ها (`prop_types`)

انواع تعریف‌شده در مدل عبارت‌اند از:

```php
public static $prop_types = [
    'text',
    'number',
    'checkbox',
    'color',
    'select',
    'multi',
    'singlemulti',
    'date',
    'time',
];
```

رفتار هر نوع بر اساس طراحی فعلی سیستم:

| نوع | کاربرد |
|---|---|
| `text` | دریافت مقدار متنی |
| `number` | دریافت مقدار عددی |
| `checkbox` | ثبت یک مقدار از نوع انتخاب‌شده/نشده |
| `color` | انتخاب از فهرست رنگ‌ها |
| `select` | انتخاب یک گزینه از فهرست |
| `singlemulti` | انتخاب یک گزینه هنگام ثبت مشخصات محصول، با امکان انتخاب چند گزینه در رابط جست‌وجو و فیلتر |
| `multi` | انتخاب چند گزینه |
| `date` | دریافت تاریخ |
| `time` | دریافت زمان |

### تفاوت `select`، `singlemulti` و `multi`

این سه نوع در تعداد گزینه‌های انتخاب‌شده و کاربردشان یکسان نیستند:

- `select`: کاربر یک گزینه را از فهرست انتخاب می‌کند.
- `singlemulti`: مقدار ثبت‌شده برای محصول یک گزینه است، اما در جست‌وجو و فیلتر امکان انتخاب چند گزینه وجود دارد.
- `multi`: امکان انتخاب چند گزینه برای مقدار ویژگی وجود دارد.

نوع `color` نیز با یک فهرست از رنگ‌ها کار می‌کند، اما برای نمایش و انتخاب رنگ‌ها کاربرد اختصاصی دارد.

## گزینه‌های ویژگی (`options`)

فیلد `options` اطلاعات گزینه‌های مرتبط با ویژگی را در قالب JSON نگه می‌دارد. طبق پیاده‌سازی فعلی، هر گزینه دارای دو مقدار `title` و `value` است:

- `title`: عنوان قابل نمایش گزینه.
- `value`: مقدار یا شناسه‌ای که برای گزینه استفاده می‌شود.

مدل سه accessor برای دسترسی به این اطلاعات فراهم می‌کند.

### `optionz`

```php
public function getOptionzAttribute()
{
    return json_decode($this->options);
}
```

JSON ذخیره‌شده در `options` را به ساختار PHP تبدیل می‌کند. خروجی، فهرست گزینه‌هاست که هر گزینه می‌تواند شامل `title` و `value` باشد.

### `dataz`

```php
public function getDatazAttribute()
{
    $result = [];

    foreach (json_decode($this->options) as $item) {
        $result[$item->title] = $item->value;
    }

    return $result;
}
```

گزینه‌ها را به آرایه‌ای با ساختار `title => value` تبدیل می‌کند.

### `datas`

```php
public function getDatasAttribute()
{
    $result = [];

    foreach (json_decode($this->options) as $item) {
        $result[$item->value] = $item->title;
    }

    return $result;
}
```

گزینه‌ها را به آرایه‌ای با ساختار `value => title` تبدیل می‌کند. این ساختار برای تبدیل مقدار ذخیره‌شده به عنوان قابل نمایش کاربرد دارد؛ برای مثال، `fullMeta()` در مدل `Product` از `datas` برای نمایش عنوان گزینه استفاده می‌کند.

## ویژگی‌های وابسته به دسته‌بندی

### رابطه `categories()`

```php
public function categories()
{
    return $this->belongsToMany(Category::class);
}
```

هر ویژگی می‌تواند به چند دسته‌بندی متصل باشد و هر دسته‌بندی نیز می‌تواند چند ویژگی داشته باشد.

هنگام ثبت یا ویرایش محصول، ویژگی‌های مرتبط با دسته‌بندی اصلی محصول مبنای تعیین مشخصات قابل ثبت قرار می‌گیرند. این ارتباط اجازه می‌دهد ویژگی‌های موردنیاز هر نوع محصول بدون تعریف ساختار ثابت و جداگانه برای هر دسته‌بندی مدیریت شوند.

## تأثیر ویژگی‌ها بر قیمت و موجودی

### `priceable`

این فیلد مشخص می‌کند آیا مقدار یک ویژگی در قیمت محصول نقش دارد یا خیر.

برای مثال، در یک محصول مانند iPhone 13 Pro Max ممکن است این موارد بر قیمت اثر بگذارند:

- ظرفیت حافظه: ۲۵۶ یا ۵۱۲ گیگابایت
- رنگ دستگاه
- تک‌سیم‌کارته یا دوسیم‌کارته بودن

با این طراحی، همه این حالت‌ها می‌توانند به یک محصول پایه تعلق داشته باشند، درحالی‌که مقادیر انتخاب‌شده در مشخصات و قیمت گزینه قابل فروش تفاوت ایجاد می‌کنند.

این ویژگی در کنار گزینه‌های مقداری محصول (`Quantity`) اهمیت دارد؛ زیرا موجودی می‌تواند برای ترکیب‌های مشخصی از ویژگی‌ها ثبت شود. برای نمونه، ممکن است از یک ترکیب ظرفیت و نوع سیم‌کارت سه عدد موجود باشد و از ترکیب دیگری فقط یک عدد.

**نکته:** `priceable` در جدول، نقش ویژگی را مشخص می‌کند؛ جزئیات محاسبه قیمت و ارتباط دقیق مقادیر ویژگی با رکوردهای موجودی باید از پیاده‌سازی `Quantity` و کد ثبت سفارش بررسی شود.

## ویژگی‌های رابط کاربری

- `label`: عنوانی که کاربر در فرم مشاهده می‌کند.
- `width`: کلاس CSS برای تعیین عرض عنصر در فرم.
- `required`: الزامی بودن مقدار هنگام ثبت محصول.
- `searchable`: حضور ویژگی در جست‌وجو و فیلتر محصولات.
- `icon`: آیکون مرتبط با ویژگی از Remix Icon.
- `sort`: ترتیب نمایش ویژگی‌ها.
- `unit`: واحد اندازه‌گیری یا نمایش مقدار.

این تنظیمات باعث می‌شوند فرم مشخصات محصول تا حد زیادی از تعریف ویژگی‌ها ساخته شود، به‌جای اینکه برای هر ویژگی به تغییر ساختار ثابت فرم یا دیتابیس نیاز باشد.

## ترجمه

فیلدهای زیر قابل ترجمه هستند:

```php
public $translatable = [
    'label',
    'unit',
];
```

کلید فنی `name` قابل ترجمه نیست؛ زیرا برای شناسایی ویژگی و دسترسی به مقدار آن در ساختارهای داده استفاده می‌شود. `label` و `unit` برای نمایش به کاربر هستند و می‌توانند در زبان‌های مختلف تغییر کنند.
