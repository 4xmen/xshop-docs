# Part

مدل `Part` برای نگهداری تنظیمات و ارجاع به اجزای قابل استفاده در سیستم قالب‌بندی سایت استفاده می‌شود. هر رکورد مشخص می‌کند کدام Theme Part از کدام Segment بارگذاری شود و در چه ترتیبی قرار بگیرد. همچنین می‌تواند به یک `Area` مرتبط باشد یا برای یک موجودیت خاص، به یک Theme سفارشی اختصاص پیدا کند.

در این معماری، **Segment نوع یا محل قرارگیری جزء قالب را مشخص می‌کند و Part مشخص می‌کند کدام پیاده‌سازی از آن جزء استفاده شود.**

## ساختار جدول `parts`

| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه رکورد |
| `area_id` | BIGINT UNSIGNED | بله | شناسه Area مرتبط، در صورت وجود |
| `segment` | VARCHAR(255) | خیر | نام Segment؛ مانند `footer` یا `menu` |
| `part` | VARCHAR(255) | خیر | نام Theme Part مورد استفاده؛ مانند `AplMenu` یا `WaveFooter` |
| `data` | LONGTEXT | خیر | داده‌های JSON تکمیلی مرتبط با Part؛ پیش‌فرض آرایه JSON خالی |
| `sort` | INT | خیر | ترتیب نمایش یا بارگذاری Part؛ پیش‌فرض `0` |
| `custom` | VARCHAR(255) | بله | مشخص‌کننده Theme سفارشی مرتبط با یک موجودیت خاص |
| `created_at` | TIMESTAMP | بله | زمان ایجاد |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی |

## مفهوم Segment و Part

### `segment`

نام Segment مشخص می‌کند جزء قالب از کدام دسته یا مسیر Segment انتخاب می‌شود. برای مثال:

- `menu`
- `footer`

این مقدار به ساختار پوشه‌های Segment در سیستم قالب مربوط است.

### `part`

مشخص می‌کند کدام پیاده‌سازی از یک Segment استفاده شود. برای مثال:

- `AplMenu` برای یک منو
- `WaveFooter` برای یک فوتر

در نتیجه، چند Theme Part می‌توانند برای یک Segment وجود داشته باشند و انتخاب مقدار `part` تعیین می‌کند کدام‌یک مورد استفاده قرار گیرد.

## Theme سفارشی برای موجودیت‌ها

### `custom`

این فیلد برای مشخص کردن Theme سفارشی یک موجودیت خاص استفاده می‌شود؛ برای مثال، اختصاص یک Landing Page اختصاصی به یک سرفصل یا موجودیت دیگر.

در این حالت، تنظیمات Part می‌توانند در چارچوب Theme سفارشی آن موجودیت قرار بگیرند، به‌جای اینکه صرفاً از تنظیمات عمومی سایت استفاده شود.

این قابلیت امکان طراحی ظاهر اختصاصی برای یک موجودیت را فراهم می‌کند؛ جزئیات نحوه تشخیص و بارگذاری این Theme به منطق پیاده‌سازی سیستم قالب وابسته است.

## داده‌های تکمیلی

### `data`

فیلد `data` برای ذخیره اطلاعات JSON تکمیلی مرتبط با Part در نظر گرفته شده است. این فیلد می‌تواند محلی برای اطلاعاتی باشد که هنگام ثبت یا بارگذاری Theme Part مورد نیاز هستند.

تا اینجا، طبق توضیح پروژه، از این فیلد استفاده عملی نشده است؛ اما می‌تواند در آینده برای قابلیت‌هایی مانند ذخیره اطلاعات تکمیلی یا اطلاعات مربوط به به‌روزرسانی تصویر پیش‌نمایش به کار گرفته شود.

### `sort`

ترتیب قرارگیری Partها را مشخص می‌کند. این فیلد امکان تعیین ترتیب استفاده از اجزای قالب را فراهم می‌کند.

## نکات پایگاه داده

- فیلد `data` دارای محدودیت `CHECK (json_valid(data))` است؛ بنابراین مقدار ذخیره‌شده باید JSON معتبر باشد.
- فیلد `area_id` در SQL ارائه‌شده کلید خارجی ندارد؛ ارتباط آن با `Area` در سطح این تعریف پایگاه داده تضمین نشده است.
- فیلد `custom` nullable است؛ بنابراین تمام Partها الزاماً به یک Theme سفارشی مربوط نیستند.
- جدول محدودیت یکتایی برای ترکیب `area_id`، `segment`، `part` و `custom` تعریف نکرده است؛ در نتیجه، از روی ساختار SQL نمی‌توان یکتایی چنین ترکیبی را نتیجه گرفت.

## متدها و روابط

### `getBladeWithData($item = null)`

این متد مسیر قالب Blade و داده‌های موردنیاز برای نمایش Theme Part را برمی‌گرداند.

ابتدا کلاس مربوط به Part را از مقدار `part` می‌سازد و سپس متد استاتیک `onMount()` همان کلاس را فراخوانی می‌کند. خروجی به شکل آرایه‌ای با دو کلید ارائه می‌شود:

- `blade`: مسیر قالب، به شکل `segments.{segment}.{part}.{part}`
- `data`: داده‌ای که متد `onMount()` برمی‌گرداند.

پارامتر `$item` اختیاری است و برای زمانی استفاده می‌شود که آماده‌سازی داده‌های Part به موجودیت جاری صفحه وابسته باشد.

برای مثال، یک Part مربوط به فوتر ممکن است بدون دریافت موجودیت خارجی، داده‌های موردنیاز خودش را آماده کند؛ در مقابل، Part نمایش شبکه‌ای محصولات یا تصاویر گالری می‌تواند موجودیت جاری را دریافت کند تا اطلاعات مناسب برای نمایش را آماده سازد.

### `getBlade()`

این متد کلاس مربوط به Part را از مقدار `part` می‌سازد، متد استاتیک `onMount($this)` را فراخوانی می‌کند و مسیر Blade را به شکل `segments.{segment}.{part}.{part}` برمی‌گرداند.

برخلاف `getBladeWithData()`، خروجی `onMount()` در مقدار بازگشتی این متد قرار نمی‌گیرد.

### `area()`

رابطه `belongsTo` با مدل [Area](area.md) برقرار می‌کند و Area مرتبط با این Part را برمی‌گرداند.

### `getAreaNameAttribute()`

Attribute محاسباتی `area_name` را ارائه می‌کند:

- اگر `area_id` مقدار داشته باشد، نام Area مرتبط را از طریق `$this->area->name` برمی‌گرداند.
- در غیر این صورت، مقدار فیلد `custom` را برمی‌گرداند.

## نحوه استفاده در قالب Blade

هنگام رندر Partها، ابتدا `getBladeWithData()` فراخوانی می‌شود و سپس مسیر قالب و داده‌های حاصل به `@include` ارسال می‌شوند:

```php
@php($p = $part->getBladeWithData($gallery))
@include($p['blade'], ['data' => $p['data']])
```

در این مثال، موجودیت `$gallery` به Part داده می‌شود تا در صورت نیاز، متد `onMount()` بتواند داده‌های مرتبط با آن را آماده کند.

برای Partهایی که به موجودیت جاری وابسته نیستند، پارامتر حذف می‌شود:

```php
@php($p = $part->getBladeWithData())
@include($p['blade'], ['data' => $p['data']])
```

این الگو برای اجزای عمومی مانند هدر و فوتر پیش‌فرض نیز استفاده می‌شود.

**نکته معماری:** هر Theme Part می‌تواند ظاهر و تنظیمات داخلی خودش را داشته باشد و در صورت نیاز، داده‌های مربوط به موجودیت جاری را نیز دریافت کند. در نتیجه، منطق ظاهر جزء قالب و داده‌های محتوایی که نمایش می‌دهد، از هم تفکیک می‌شوند.
