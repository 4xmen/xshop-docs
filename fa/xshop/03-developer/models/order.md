# Order

مدل `Order` یک ردیف از اقلام سفارش را نگه می‌دارد. هر رکورد به یک فاکتور و یک محصول مرتبط است و اطلاعاتی مانند تعداد، موجودی انتخاب‌شده و مبلغ کل آن ردیف را ذخیره می‌کند.

یک فاکتور می‌تواند چندین سفارش داشته باشد؛ اطلاعات کلی پرداخت و فاکتور در مدل [Invoice](invoice.md) نگهداری می‌شود.

## ساختار جدول `orders`

| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه سفارش |
| `invoice_id` | BIGINT UNSIGNED | خیر | شناسه فاکتور مرتبط؛ مرتبط با جدول `invoices` |
| `product_id` | BIGINT UNSIGNED | خیر | شناسه محصول سفارش‌داده‌شده؛ مرتبط با جدول `products` |
| `quantity_id` | BIGINT UNSIGNED | بله | شناسه موجودی یا نوع محصول انتخاب‌شده؛ مرتبط با مدل [Quantity](./quantity.md) |
| `count` | INT | بله | تعداد سفارش از محصول یا موجودی انتخاب‌شده؛ پیش‌فرض `1` |
| `price_total` | DECIMAL(20,2) UNSIGNED | خیر | مبلغ کل این ردیف سفارش، برابر با تعداد ضرب‌در مبلغ واحد |
| `data` | LONGTEXT | بله | اطلاعات ویژگی‌های (`prop`) موجودی انتخاب‌شده به‌صورت JSON، برای دسترسی آسان هنگام نمایش گروهی |
| `created_at` | TIMESTAMP | بله | زمان ایجاد |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی |

## روابط و متدها

### `product()`

رابطه `belongsTo` با مدل [Product](product.md) برقرار می‌کند و محصول مربوط به ردیف سفارش را برمی‌گرداند.

### `quantity()`

رابطه `belongsTo` با مدل [Quantity](./quantity.md) برقرار می‌کند و موجودی یا نوع انتخاب‌شده برای محصول را برمی‌گرداند.

از آنجا که `quantity_id` می‌تواند `NULL` باشد، هر سفارش الزاماً به یک رکورد `Quantity` متصل نیست.

### `invoice()`

رابطه `belongsTo` با مدل [Invoice](invoice.md) برقرار می‌کند و فاکتور مربوط به سفارش را برمی‌گرداند.

## نکات پایگاه داده

- فیلد `data` با محدودیت `CHECK (json_valid(data))` کنترل می‌شود؛ بنابراین مقدار غیر `NULL` آن باید JSON معتبر باشد.
- حذف فاکتور باعث حذف سفارش‌های وابسته می‌شود؛ رابطه `invoice_id` دارای `ON DELETE CASCADE` است.
- حذف محصول نیز باعث حذف سفارش‌های وابسته به آن می‌شود؛ رابطه `product_id` دارای `ON DELETE CASCADE` است.
- در SQL ارائه‌شده، برای `quantity_id` کلید خارجی تعریف نشده است؛ بنابراین یکپارچگی ارجاع آن به جدول موجودی‌ها توسط این تعریف پایگاه داده تضمین نمی‌شود.
- فیلد `count` با وجود پیش‌فرض `1`، همچنان `NULL` را می‌پذیرد. این مورد برای محصولات مجازی بی ‌معنی است.
