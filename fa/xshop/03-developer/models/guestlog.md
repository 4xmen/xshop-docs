# GuestLog

ثبت رویدادهای مهمانان سایت برای کنترل تعداد درخواست‌ها و جلوگیری از استفاده بیش‌ازحد از قابلیت‌های حساس. از این اطلاعات برای محدود کردن درخواست‌هایی مانند احراز هویت، ثبت‌نام، جست‌وجو و ارسال پیامک استفاده می‌شود تا از ایجاد فشار غیرضروری روی سرور جلوگیری شود.

این اطلاعات توسط منطق داخلی سیستم مصرف می‌شوند و در پنل مدیریت نمایش داده نمی‌شوند.

## جدول `guest_logs`

| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه یکتای رویداد |
| `ip` | VARCHAR(45) | خیر | آدرس IP مهمان مرتبط با رویداد؛ طول فیلد امکان نگهداری آدرس‌های IPv4 و IPv6 را فراهم می‌کند |
| `action` | VARCHAR(255) | خیر | نوع رویداد ثبت‌شده |
| `loggable_type` | VARCHAR(255) | بله | نوع موجودیت مرتبط با رویداد؛ بخشی از رابطه چندریختی (Polymorphic) |
| `loggable_id` | BIGINT UNSIGNED | بله | شناسه موجودیت مرتبط با رویداد؛ بخشی از رابطه چندریختی |
| `created_at` | TIMESTAMP | بله | تاریخ ایجاد رویداد |
| `updated_at` | TIMESTAMP | بله | تاریخ آخرین ویرایش رکورد |

## ویژگی‌ها و متدها

### `$actions`

فهرست انواع رویدادهای تعریف‌شده در سیستم:

- `login`: درخواست ورود
- `register`: درخواست ثبت‌نام
- `search`: درخواست جست‌وجو
- `sms`: درخواست مرتبط با پیامک

این فهرست برای مشخص‌کردن انواع رویدادهایی است که سیستم از آن‌ها استفاده می‌کند.

## نحوه استفاده

رکوردهای این جدول توسط سیستم برای پیگیری فعالیت مهمانان و اعمال محدودیت روی درخواست‌های حساس استفاده می‌شوند. فیلد `ip` امکان مرتبط‌کردن رویدادها با آدرس IP را فراهم می‌کند و فیلدهای `action`، `loggable_type` و `loggable_id` اطلاعات مربوط به نوع رویداد و موجودیت مرتبط با آن را نگهداری می‌کنند.

این مدل متد اختصاصی ارائه‌شده‌ای ندارد و اطلاعات آن مستقیماً در فرایندهای داخلی سیستم مصرف می‌شوند.
