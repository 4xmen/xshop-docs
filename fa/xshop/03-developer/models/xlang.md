# Xlang

مدل `Xlang` برای مدیریت زبان‌های سایت و قابلیت چندزبانه‌سازی استفاده می‌شود. زبان‌ها از طریق پیشوند URL از یکدیگر تفکیک می‌شوند؛ برای مثال، مسیر اصلی سایت برای زبان پیش‌فرض و مسیرهایی مانند `/de` و `/fa` برای زبان‌های دیگر استفاده می‌شوند.

نام `Xlang` برای جلوگیری از تداخل اسمی با سیستم زبان لاراول و پکیج‌های مرتبط با `Lang` انتخاب شده است.

## ساختار داده
| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه یکتای زبان |
| `name` | VARCHAR(255) | خیر | نام زبان |
| `tag` | VARCHAR(7)، unique | خیر | کد زبان و پیشوند URL؛ مانند `fa` یا `de` |
| `rtl` | TINYINT(1) | خیر | مشخص می‌کند زبان راست‌به‌چپ است یا خیر؛ مقدار پیش‌فرض `0` |
| `is_default` | TINYINT(1) | خیر | مشخص می‌کند زبان، زبان پیش‌فرض سایت است یا خیر؛ مقدار پیش‌فرض `0` |
| `img` | VARCHAR(255) | بله | نام فایل تصویر پرچم زبان |
| `emoji` | VARCHAR(255) | بله | ایموجی پرچم زبان |
| `sort` | TINYINT | خیر | ترتیب نمایش زبان‌ها؛ مقدار پیش‌فرض `0` |
| `deleted_at` | TIMESTAMP | بله | زمان حذف نرم زبان |
| `created_at` | TIMESTAMP | بله | زمان ایجاد رکورد |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی رکورد |

## متدها

### `imgUrl()`

آدرس تصویر بهینه‌شده پرچم زبان را برمی‌گرداند؛ در صورت نبود تصویر، از لوگوی سایت به‌عنوان fallback استفاده می‌شود.

### `imgOriginalUrl()`

آدرس تصویر اصلی پرچم زبان را برمی‌گرداند؛ در صورت نبود تصویر، از لوگوی سایت به‌عنوان fallback استفاده می‌شود.

### `getRouteKeyName()`

فیلد `tag` را برای Route Model Binding به‌جای `id` استفاده می‌کند.

## نکات

- فیلد `tag` دارای ایندکس یکتا است؛ بنابراین هر زبان باید کد منحصربه‌فردی داشته باشد.
- پیشوند زبان در مسیرهای سایت اعمال می‌شود و صفحات مختلف، از جمله پست‌ها و دسته‌بندی‌ها، از ساختار چندزبانه پیروی می‌کنند.
- زبان پیش‌فرض سایت از طریق `is_default` مشخص می‌شود. تعیین یکتایی زبان پیش‌فرض باید در منطق برنامه مدیریت شود؛ ساختار جدول به‌تنهایی آن را تضمین نمی‌کند.
- فیلد `rtl` برای تشخیص زبان‌های راست‌به‌چپ، مانند فارسی و عربی، استفاده می‌شود.
- فیلد `sort` ترتیب نمایش زبان‌ها را مشخص می‌کند.
- فایل‌های زبان با تعریف فایل‌های JSON در مسیر `resources/lang` ایجاد می‌شوند. برای مثال، فایل‌های `ar.json`، `de.json`، `fa.json` و `fr.json` در این مسیر قرار دارند.
- زبان انگلیسی زبان اصلی محتوا است و برای آن فایل ترجمه جداگانه‌ای در نظر گرفته نشده است. مدیر می‌تواند فایل‌های زبان موجود را از طریق ویرایشگر مدیریت کند.
- فایل‌های پرچم در مسیر `langz/` و نسخه‌های بهینه‌شده آن‌ها در مسیر `langz/optimized-` قابل دسترسی هستند.
- فیلد `deleted_at` برای ثبت زمان حذف نرم در نظر گرفته شده است؛ فعال بودن Soft Deletes به تنظیمات مدل وابسته است.
