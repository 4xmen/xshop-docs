# AdminLog

Model reference · `App\Models\AdminLog`

### 1. Model

مدل ثبت گزارش عملکرد مدیران سیستم، شامل Admin و Developer ویا User این مدل برای ثبت عملیات انجام‌شده روی منابع سیستم طراحی شده است و می‌تواند به‌عنوان سابقه فعالیت، گزارش کار و ابزاری برای بررسی مسئولیت‌پذیری مدیران در سیستم‌های سازمانی مورد استفاده قرار گیرد.

- مثلا کاربر x دسته‌بندی z را ویرایش کرد
- مثال دیگر: کاربر y مثلا یک محصول را حذف کرد

عملیات اجرایی ثبت می‌شوند، نه فعالیت‌های صرفاً نمایشی؛ برای مثال، مشاهده فهرست اطلاعات به‌تنهایی لاگ ایجاد نمی‌کند.

### 3. Extra description of table fields

**`admin_logs.user_id`**

مشخص می‌کند کدام کاربر عملیات را انجام داده است. این فیلد به جدول `users` ارجاع می‌دهد.

حذف کاربر مرتبط با لاگ به دلیل محدودیت `ON DELETE RESTRICT` در دیتابیس مجاز نیست؛ بنابراین سابقه عملکرد کاربران حفظ می‌شود.

مستندات مدل مرتبط: [User](user.md).

**`admin_logs.action`**

نوع عملیات انجام‌شده را مشخص می‌کند. نمونه‌های متداول عبارت‌اند از:

- `create` — ایجاد رکورد
- `update` — ویرایش رکورد؛ از جمله عملیاتی که در منطق سیستم با عنوان `bringup` تعریف شده‌اند.
- `delete` — حذف رکورد
- `restore` — بازیابی رکورد حذف‌شده

همچنین عملیات اختصاصی تعریف‌شده در Controllerها می‌توانند در این فیلد ثبت شوند. مقدار این فیلد بیانگر نوع عملیات است، نه جزئیات کامل تغییرات اعمال‌شده.

**`admin_logs.loggable_type` و `admin_logs.loggable_id`**

این دو فیلد با هم مشخص می‌کنند عملیات روی کدام مدل و کدام رکورد انجام شده است. این ساختار برای ارجاع چندریختی (Polymorphic) به منابع مختلف طراحی شده است.

برای مثال، اگر عملیاتی روی یک محصول انجام شود، `loggable_type` نوع مدل محصول و `loggable_id` شناسه همان محصول را مشخص می‌کند.

هر دو فیلد اختیاری هستند؛ بنابراین یک لاگ می‌تواند بدون ارجاع به رکورد مشخصی ثبت شود.

**ثبت عملیات گروهی (Bulk Action)**

اگر مدیر یک عملیات گروهی روی چند رکورد انجام دهد، برای هر رکورد تحت تأثیر عملیات یک لاگ جداگانه ثبت می‌شود. در نتیجه، سابقه عملکرد هر رکورد به‌صورت مستقل قابل بررسی خواهد بود.

**کاربرد سازمانی و مسئولیت‌پذیری**

این جدول می‌تواند برای بررسی سوابق اجرایی مدیران، تهیه گزارش عملکرد و پیگیری عملیات انجام‌شده در سیستم‌های سازمانی استفاده شود.

بااین‌حال، وجود یک رکورد در این جدول به‌تنهایی اثبات قطعی تمام جزئیات یک عملیات نیست؛ این جدول نوع عملیات، عامل آن و مرجع مرتبط را نگهداری می‌کند و لزوماً شامل مقادیر قبل و بعد از تغییر یا سایر جزئیات اجرایی نیست.

### 4. Methods

مستندات مدل مرتبط: [User](user.md).
