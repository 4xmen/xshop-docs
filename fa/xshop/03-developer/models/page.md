# Page

مدل `Page` برای مدیریت صفحات و محتوای متنی سایت استفاده می‌شود. هر صفحه می‌تواند زیر مجموعه یک صفحه دیگر نیز باشد و قابلیت‌هایی مانند انتشار یا پیش‌نویس بودن، شمارش بازدید، قالب سفارشی و تنظیمات سئو را دارد.

## ساختار جدول `pages`

| فیلد                | نوع | Nullable | توضیحات |
|---------------------|---|---|---|
| `id`                | BIGINT UNSIGNED | خیر | شناسه صفحه |
| `title`             | TEXT | خیر | عنوان صفحه |
| `slug`              | VARCHAR(255) | خیر | شناسه متنی صفحه در URL؛ یکتا |
| `subtitle`          | TEXT | خیر | زیرعنوان صفحه |
| `body`              | LONGTEXT | خیر | محتوای اصلی صفحه |
| `parent_id`         | BIGINT UNSIGNED | خیر | شناسه  صفحه؛ مرتبط با جدول `groups` |
| `status`            | TINYINT UNSIGNED | خیر | وضعیت صفحه؛ `0` پیش‌نویس و `1` منتشرشده |
| `view`              | INT UNSIGNED | خیر | تعداد بازدید صفحه |
| `icon`              | VARCHAR(128) NULL | بله | نام آیکون Remix Icon انتخاب‌شده از طریق Icon Picker |
| `theme`             | LONGTEXT | بله | اطلاعات JSON مربوط به قالب سفارشی همین صفحه |
| `canonical`         | TEXT | بله | آدرس Canonical برای سئو |
| `markups`           | TEXT | بله | داده‌های Schema Markup اختصاصی صفحه |
| `deleted_at`        | TIMESTAMP | بله | زمان حذف نرم |
| `created_at`        | TIMESTAMP | بله | زمان ایجاد |
| `updated_at`        | TIMESTAMP | بله | زمان آخرین به‌روزرسانی |

## وضعیت و نمایش صفحه

### `status`

وضعیت صفحه را مشخص می‌کند:

- `0`: پیش‌نویس (`Draft`)
- `1`: منتشرشده (`Published`)

### `view`

تعداد بازدیدهای صفحه را نگه می‌دارد.


### `icon`

نام آیکون Remix Icon انتخاب‌شده برای صفحه را نگه می‌دارد. انتخاب آیکون از طریق Icon Picker انجام می‌شود.

## قالب سفارشی صفحه

### `theme`

اطلاعات مربوط به قالب سفارشی همین صفحه را به‌صورت JSON نگه می‌دارد.

این قابلیت اجازه می‌دهد یک صفحه قالب اختصاصی خود را داشته باشد، بدون اینکه الزاماً از ظاهر عمومی سایت استفاده کند. معماری قالب‌های سفارشی و نحوه بارگذاری اجزای آن‌ها در مستند [Part](part.md) توضیح داده شده است.

## تنظیمات سئو

### `canonical`

آدرس Canonical صفحه را نگه می‌دارد تا URL مرجع آن برای موتورهای جست‌وجو مشخص شود.


### `markups`

برای نگهداری Schema Markup اختصاصی صفحه استفاده می‌شود. این اطلاعات می‌توانند ساختار داده‌های نشانه‌گذاری‌شده مرتبط با همین صفحه را مشخص کنند.


## روابط پایگاه داده

- `parent_id` به جدول `pages` اشاره می‌کند و با حذف سرفصل دارای `ON DELETE RESTRICT` است.
- فیلد `slug`  به‌صورت جداگانه یکتا هستند.
- فیلد `theme` دارای محدودیت `CHECK (json_valid(theme))` است؛ بنابراین مقدار غیر `NULL` آن باید JSON معتبر باشد.

## ویژگی‌ها، متدها و روابط

### ترجمه‌پذیری

```php
public $translatable = ['title', 'subtitle', 'body'];
```

فیلدهای `title`، `subtitle` و `body` قابلیت ترجمه دارند.

### `parent()`

رابطه `belongsTo` با همین مدل برقرار می‌کند و صفحه والد را از طریق فیلد `parent_id` برمی‌گرداند.

### `children()`

رابطه `hasMany` با همین مدل برقرار می‌کند و صفحات فرزند را که `parent_id` آن‌ها با شناسه صفحه فعلی برابر است، برمی‌گرداند.


### `getRouteKeyName()`

مقدار `slug` را به‌عنوان کلید مورد استفاده برای Route Model Binding معرفی می‌کند؛ بنابراین در این مدل، شناسه متنی صفحه برای شناسایی آن در Route استفاده می‌شود.

### `markupKeywords()`

فهرستی از متغیرهای قابل استفاده در Schema Markup را ارائه می‌کند. در بخش ارائه‌شده از متد، موارد زیر مشخص هستند:

- `app.name`: نام برنامه از تنظیم `app.name`
- `title`: عنوان صفحه

هر مورد شامل عنوان قابل نمایش و مقدار متناظر است. فهرست کامل متغیرها به ادامه پیاده‌سازی متد وابسته است.

### `registerMediaConversions(?Media $media = null)`

تبدیل‌های تصویری مورد استفاده برای تصاویر صفحه را با استفاده از Spatie Media Library ثبت می‌کند.

- نام تبدیل: `page-image`
- ابعاد تصویر از تنظیم `page_thumb` و تابع `imageSizeConvertValidate()` دریافت می‌شود.
- تصویر با ابعاد تعیین‌شده برش می‌خورد.
- بهینه‌سازی تصویر و افزایش وضوح با `sharpen(10)` اعمال می‌شود.
- تبدیل به‌صورت `nonQueued()` اجرا می‌شود؛ یعنی در صف پردازش قرار نمی‌گیرد.
- فرمت خروجی از تنظیم `optimize` گرفته می‌شود و اگر مقدار آن `false` باشد، `webp` انتخاب می‌شود.
- در صورت فعال بودن تنظیم `watermark`، لوگوی `public/upload/images/logo.png` به‌عنوان واترمارک در پایین سمت چپ تصویر قرار می‌گیرد. اندازه و میزان شفافیت آن از تنظیمات برنامه دریافت می‌شوند.

### `imgUrl()`

آدرس تصویر بهینه‌شده صفحه را برمی‌گرداند. اگر تصویر رسانه‌ای وجود داشته باشد، URL تبدیل `page-image` از اولین رسانه دریافت می‌شود؛ در غیر این صورت، آدرس لوگوی پیش‌فرض سایت برگردانده می‌شود.

### `orgUrl()`

آدرس اصلی اولین رسانه صفحه را بدون انتخاب تبدیل `page-image` برمی‌گرداند. اگر رسانه‌ای وجود نداشته باشد، آدرس لوگوی پیش‌فرض سایت برگردانده می‌شود.

### `attachs()`

رابطه `morphMany` با مدل [Attachment](attachment.md) برقرار می‌کند و فایل‌ها و پیوست‌های مرتبط با صفحه را برمی‌گرداند.

### `webUrl()`

آدرس عمومی صفحه را با استفاده از Route به نام `client.page` و مقدار `slug` تولید می‌کند؛ سپس `fixUrlLang()` را برای اصلاح آدرس متناسب با منطق زبان سایت اعمال می‌کند.

### `webUrlLang($lang)`

آدرس Route عمومی صفحه را تولید می‌کند و سپس با جایگزینی `config('app.url')`، پیشوند زبان مشخص‌شده را به URL اضافه می‌کند.

رفتار دقیق این متد به ساختار URL برنامه و مقدار `$lang` وابسته است.

### `markup()`

این متد برای تولید Schema Markup صفحه در نظر گرفته شده است. چون بدنه متد در کد ارسالی موجود نیست، جزئیات نوع Schema و نحوه تولید خروجی از اطلاعات فعلی قابل تعیین نیست.
