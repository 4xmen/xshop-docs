# Post

مدل `Post` برای مدیریت نوشته‌ها و محتوای متنی سایت استفاده می‌شود. هر نوشته به یک سرفصل (`Group`) و یک کاربر (`User`) مرتبط است و قابلیت‌هایی مانند انتشار یا پیش‌نویس بودن، شمارش بازدید، سنجاق‌کردن نوشته‌های مهم، فهرست مطالب خودکار، قالب سفارشی و تنظیمات سئو را دارد.

## ساختار جدول `posts`

| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه نوشته |
| `title` | TEXT | خیر | عنوان نوشته |
| `slug` | VARCHAR(255) | خیر | شناسه متنی نوشته در URL؛ یکتا |
| `subtitle` | TEXT | خیر | زیرعنوان نوشته |
| `body` | LONGTEXT | خیر | محتوای اصلی نوشته |
| `group_id` | BIGINT UNSIGNED | خیر | شناسه سرفصل نوشته؛ مرتبط با جدول `groups` |
| `user_id` | BIGINT UNSIGNED | خیر | شناسه نویسنده؛ مرتبط با جدول `users` |
| `status` | TINYINT UNSIGNED | خیر | وضعیت نوشته؛ `0` پیش‌نویس و `1` منتشرشده |
| `view` | INT UNSIGNED | خیر | تعداد بازدید نوشته |
| `is_pinned` | TINYINT(1) | خیر | مشخص می‌کند نوشته به‌عنوان مطلب مهم سنجاق شده است یا خیر |
| `hash` | VARCHAR(14) | خیر | شناسه کوتاه نوشته برای استفاده در لینک کوتاه |
| `like` | INT UNSIGNED | خیر | تعداد پسندها |
| `dislike` | INT UNSIGNED | خیر | تعداد نپسندیدن‌ها |
| `icon` | VARCHAR(128) NULL | بله | نام آیکون Remix Icon انتخاب‌شده از طریق Icon Picker |
| `table_of_contents` | TINYINT(1) | خیر | فعال یا غیرفعال بودن فهرست مطالب خودکار |
| `theme` | LONGTEXT | بله | اطلاعات JSON مربوط به قالب سفارشی همین نوشته |
| `canonical` | TEXT | بله | آدرس Canonical برای سئو |
| `promote` | VARCHAR(255) | بله | فیلد در نظر گرفته‌شده برای قابلیت انتشار یا معرفی محتوا در سایت دیگر؛ هنوز پیاده‌سازی نشده است |
| `keyword` | TEXT | بله | کلمات کلیدی مرتبط با سئو |
| `deleted_at` | TIMESTAMP | بله | زمان حذف نرم |
| `created_at` | TIMESTAMP | بله | زمان ایجاد |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی |
| `markups` | TEXT | بله | داده‌های Schema Markup اختصاصی نوشته |

## وضعیت و نمایش نوشته

### `status`

وضعیت نوشته را مشخص می‌کند:

- `0`: پیش‌نویس (`Draft`)
- `1`: منتشرشده (`Published`)

### `view`

تعداد بازدیدهای نوشته را نگه می‌دارد.

### `is_pinned`

برای مشخص‌کردن نوشته‌های مهم و سنجاق‌شده استفاده می‌شود؛ مشابه قابلیت Sticky Posts در وردپرس.

### `like` و `dislike`

تعداد پسندها و نپسندیدن‌های نوشته را نگه می‌دارند.

### `hash`

یک شناسه کوتاه برای نوشته است که طبق کاربرد فعلی موردنظر، برای لینک کوتاه استفاده می‌شود. این فیلد در دیتابیس یکتا است.

### `icon`

نام آیکون Remix Icon انتخاب‌شده برای نوشته را نگه می‌دارد. انتخاب آیکون از طریق Icon Picker انجام می‌شود.

## فهرست مطالب خودکار

### `table_of_contents`

این فیلد تعیین می‌کند فهرست مطالب خودکار برای نوشته فعال باشد یا خیر.

فهرست مطالب بر اساس تیترهای HTML از `h1` تا `h6` ساخته می‌شود.

## قالب سفارشی نوشته

### `theme`

اطلاعات مربوط به قالب سفارشی همین نوشته را به‌صورت JSON نگه می‌دارد.

این قابلیت اجازه می‌دهد یک نوشته قالب اختصاصی خود را داشته باشد، بدون اینکه الزاماً از ظاهر عمومی سایت استفاده کند. معماری قالب‌های سفارشی و نحوه بارگذاری اجزای آن‌ها در مستند [Part](part.md) توضیح داده شده است.

## تنظیمات سئو

### `canonical`

آدرس Canonical نوشته را نگه می‌دارد تا URL مرجع آن برای موتورهای جست‌وجو مشخص شود.

### `keyword`

کلمات کلیدی مرتبط با نوشته را برای تنظیمات سئو نگه می‌دارد.

### `markups`

برای نگهداری Schema Markup اختصاصی نوشته استفاده می‌شود. این اطلاعات می‌توانند ساختار داده‌های نشانه‌گذاری‌شده مرتبط با همین نوشته را مشخص کنند.

## قابلیت برنامه‌ریزی‌شده: `promote`

فیلد `promote` برای قابلیتی در نظر گرفته شده که قرار است امکان معرفی یا انتشار نوشته در یک سایت دیگر را فراهم کند؛ مشابه انتشار محتوا از طریق سازوکارهایی مانند RSS Push، همراه با لینک به مطلب اصلی.

این ایده برای محصولات نیز در نظر گرفته شده است، اما طبق وضعیت فعلی پروژه، قابلیت هنوز پیاده‌سازی نشده است. بنابراین نباید آن را به‌عنوان ویژگی فعال سیستم در نظر گرفت.

## روابط پایگاه داده

- `group_id` به جدول `groups` اشاره می‌کند و با حذف سرفصل دارای `ON DELETE RESTRICT` است.
- `user_id` به جدول `users` اشاره می‌کند و با حذف کاربر دارای `ON DELETE RESTRICT` است.
- فیلدهای `slug` و `hash` هرکدام به‌صورت جداگانه یکتا هستند.
- فیلد `theme` دارای محدودیت `CHECK (json_valid(theme))` است؛ بنابراین مقدار غیر `NULL` آن باید JSON معتبر باشد.

## ویژگی‌ها، متدها و روابط

### ترجمه‌پذیری

```php
public $translatable = ['title', 'subtitle', 'body'];
```

فیلدهای `title`، `subtitle` و `body` قابلیت ترجمه دارند.

### `groups()`

رابطه `belongsToMany` با مدل [Group](group.md) برقرار می‌کند. از طریق این رابطه، سرفصل‌های مرتبط با نوشته دریافت می‌شوند.

توجه داشته باشید که این رابطه از جدول واسط پیش‌فرض Laravel برای ارتباط چندبه‌چند استفاده می‌کند؛ نام و ساختار جدول واسط در کد ارائه‌شده مشخص نشده است.

### `author()`

رابطه `belongsTo` با مدل `User` برقرار می‌کند و نویسنده نوشته را برمی‌گرداند. کلید خارجی `user_id` و کلید مرجع `id` است.

### `getRouteKeyName()`

مقدار `slug` را به‌عنوان کلید مورد استفاده برای Route Model Binding معرفی می‌کند؛ بنابراین در این مدل، شناسه متنی نوشته برای شناسایی آن در Route استفاده می‌شود.

### `markupKeywords()`

فهرستی از متغیرهای قابل استفاده در Schema Markup را ارائه می‌کند. در بخش ارائه‌شده از متد، موارد زیر مشخص هستند:

- `app.name`: نام برنامه از تنظیم `app.name`
- `title`: عنوان نوشته

هر مورد شامل عنوان قابل نمایش و مقدار متناظر است. فهرست کامل متغیرها به ادامه پیاده‌سازی متد وابسته است.

### `registerMediaConversions(?Media $media = null)`

تبدیل‌های تصویری مورد استفاده برای تصاویر نوشته را با استفاده از Spatie Media Library ثبت می‌کند.

- نام تبدیل: `post-image`
- ابعاد تصویر از تنظیم `post_thumb` و تابع `imageSizeConvertValidate()` دریافت می‌شود.
- تصویر با ابعاد تعیین‌شده برش می‌خورد.
- بهینه‌سازی تصویر و افزایش وضوح با `sharpen(10)` اعمال می‌شود.
- تبدیل به‌صورت `nonQueued()` اجرا می‌شود؛ یعنی در صف پردازش قرار نمی‌گیرد.
- فرمت خروجی از تنظیم `optimize` گرفته می‌شود و اگر مقدار آن `false` باشد، `webp` انتخاب می‌شود.
- در صورت فعال بودن تنظیم `watermark`، لوگوی `public/upload/images/logo.png` به‌عنوان واترمارک در پایین سمت چپ تصویر قرار می‌گیرد. اندازه و میزان شفافیت آن از تنظیمات برنامه دریافت می‌شوند.

### `imgUrl()`

آدرس تصویر بهینه‌شده نوشته را برمی‌گرداند. اگر تصویر رسانه‌ای وجود داشته باشد، URL تبدیل `post-image` از اولین رسانه دریافت می‌شود؛ در غیر این صورت، آدرس لوگوی پیش‌فرض سایت برگردانده می‌شود.

### `orgUrl()`

آدرس اصلی اولین رسانه نوشته را بدون انتخاب تبدیل `post-image` برمی‌گرداند. اگر رسانه‌ای وجود نداشته باشد، آدرس لوگوی پیش‌فرض سایت برگردانده می‌شود.

### `spendTime()`

زمان تخمینی مطالعه نوشته را بر اساس محتوای آن محاسبه می‌کند.

ابتدا تگ‌های HTML از `body` حذف می‌شوند، سپس طول رشته حاصل بر `1350` تقسیم و به عدد صحیح بالاتر گرد می‌شود. در نهایت، عدد محاسبه‌شده همراه با عبارت ترجمه‌پذیر `minute(s)` برگردانده می‌شود.

این محاسبه بر اساس طول رشته است، نه شمارش دقیق کلمات؛ بنابراین زمان حاصل یک تخمین مبتنی بر پیاده‌سازی فعلی است.

### `comments()`

رابطه `morphMany` با مدل [Comment](comment.md) برقرار می‌کند و نظرات مرتبط با نوشته را برمی‌گرداند.

### `approvedComments()`

در پیاده‌سازی فعلی، این متد نیز همان رابطه `morphMany` با مدل `Comment` را برمی‌گرداند.

در کد ارائه‌شده هیچ شرطی برای محدود کردن نتایج به نظرات تأییدشده وجود ندارد؛ بنابراین نام متد با رفتار فعلی آن کاملاً هم‌خوان نیست، مگر اینکه فیلتر تأیید در جای دیگری اعمال شود.

### `mainGroup()`

رابطه `belongsTo` با مدل [Group](group.md) برقرار می‌کند و سرفصل اصلی نوشته را از طریق `group_id` برمی‌گرداند.

این رابطه با `groups()` تفاوت دارد: `mainGroup()` سرفصل اصلی را از ستون `group_id` دریافت می‌کند، درحالی‌که `groups()` یک رابطه چندبه‌چند است.

### `attachs()`

رابطه `morphMany` با مدل [Attachment](attachment.md) برقرار می‌کند و فایل‌ها و پیوست‌های مرتبط با نوشته را برمی‌گرداند.

### `webUrl()`

آدرس عمومی نوشته را با استفاده از Route به نام `client.post` و مقدار `slug` تولید می‌کند؛ سپس `fixUrlLang()` را برای اصلاح آدرس متناسب با منطق زبان سایت اعمال می‌کند.

### `webUrlLang($lang)`

آدرس Route عمومی نوشته را تولید می‌کند و سپس با جایگزینی `config('app.url')`، پیشوند زبان مشخص‌شده را به URL اضافه می‌کند.

رفتار دقیق این متد به ساختار URL برنامه و مقدار `$lang` وابسته است.

### `markup()`

این متد برای تولید Schema Markup نوشته در نظر گرفته شده است. چون بدنه متد در کد ارسالی موجود نیست، جزئیات نوع Schema و نحوه تولید خروجی از اطلاعات فعلی قابل تعیین نیست.
