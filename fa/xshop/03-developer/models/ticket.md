# Ticket

مدل `Ticket` برای مدیریت تیکت‌های پشتیبانی مشتریان استفاده می‌شود. هر تیکت می‌تواند شامل پیام مشتری، پاسخ مدیر، وضعیت رسیدگی و تیکت‌های زیرمجموعه باشد. همچنین امکان ارزیابی تیکت و ثبت امتیاز برای آن وجود دارد.

## ساختار داده
| فیلد | نوع | Nullable | توضیحات |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | خیر | شناسه یکتای تیکت |
| `title` | VARCHAR(128) | بله | عنوان تیکت؛ برای تیکت‌های والد بدون دسته‌بندی |
| `customer_id` | BIGINT UNSIGNED | خیر | شناسه مشتری ارسال‌کننده تیکت |
| `user_id` | BIGINT UNSIGNED | بله | شناسه کاربر یا مدیر ارسال‌کننده پاسخ |
| `body` | TEXT | خیر | متن پیام تیکت؛ بدون ترجمه |
| `status` | ENUM('PENDING', 'ANSWERED', 'CLOSED') | خیر | وضعیت رسیدگی به تیکت |
| `answer` | TEXT | بله | متن پاسخ مدیر |
| `parent_id` | INT UNSIGNED | بله | شناسه تیکت والد، برای مشخص‌کردن تیکت‌های زیرمجموعه |
| `created_at` | TIMESTAMP | بله | زمان ایجاد تیکت |
| `updated_at` | TIMESTAMP | بله | زمان آخرین به‌روزرسانی تیکت |

## ویژگی‌ها

### `$ticket_statuses`

فهرست وضعیت‌های معتبر تیکت را مشخص می‌کند:

- `PENDING`: در انتظار رسیدگی
- `ANSWERED`: پاسخ داده‌شده
- `CLOSED`: بسته‌شده

وضعیت پیش‌فرض در دیتابیس `PENDING` است.

## روابط

- `customer()`: رابطه‌ی `belongsTo` با مدل `Customer`؛ مشتری ارسال‌کننده تیکت.
- `user()`: رابطه‌ی `belongsTo` با مدل `User`؛ مدیر یا کاربر مرتبط با پاسخ.
- `subTickets()`: رابطه‌ی `hasMany` با مدل `Ticket`؛ تیکت‌های زیرمجموعه که بر اساس `id` به‌صورت صعودی مرتب می‌شوند.

## متدها

### `evaluations()`

ارزیابی‌های قابل استفاده برای تیکت را برمی‌گرداند؛ شامل ارزیابی‌های عمومی، ارزیابی‌های اختصاص‌یافته به مدل `Ticket` و ارزیابی‌های اختصاص‌یافته به تیکت فعلی.

## نکات

- مقدار `customer_id` اجباری است و کلید خارجی آن به مدل `Customer` اشاره دارد. حذف مشتری باعث حذف تیکت‌های مرتبط می‌شود (`ON DELETE CASCADE`).
- مقدار `user_id` اختیاری است و به مدل `User` اشاره دارد. حذف کاربر مرتبط نیز باعث حذف تیکت‌های مرتبط می‌شود (`ON DELETE CASCADE`).
- فیلد `parent_id` برای ایجاد ساختار والد و زیرمجموعه استفاده می‌شود. در جدول، برای این فیلد ایندکس تعریف شده، اما کلید خارجی ثبت نشده است.
- تیکت قابلیت ارزیابی دارد و می‌توان با استفاده از سیستم امتیازدهی `Rate` به آن امتیاز داد.
- فیلد `answer` برای ذخیره پاسخ مدیر در نظر گرفته شده است؛ درحالی‌که `body` متن اصلی پیام تیکت را نگهداری می‌کند.
- فیلد `status` از نوع `ENUM` است و فقط مقادیر `PENDING`، `ANSWERED` و `CLOSED` را می‌پذیرد.
