
# راهنمای ساخت Theme Part 

## ۱. مقدمه

در xShop، **Theme Part** بخشی مستقل از قالب وب‌سایت است که می‌توان آن را در محل‌های مختلف رابط کاربری قرار داد و ظاهر و رفتار آن را متناسب با نیاز پروژه توسعه داد.

برای مثال، می‌توانید Theme Partهایی برای نمایش آخرین محصولات، اسلایدر، فهرست دسته‌بندی‌ها، فرم تماس، هدر یا فوتر وب‌سایت ایجاد کنید.

هر Theme Part می‌تواند شامل فایل‌های زیر باشد:

- **PHP:** برای تعریف رفتار و چرخه حیات Theme Part
- **Blade:** برای پیاده‌سازی ساختار HTML و نمایش اطلاعات
- **SCSS:** برای تعریف استایل‌ها
- **JavaScript:** برای افزودن رفتارهای تعاملی
- **Screenshot:** برای نمایش پیش‌نمایش Theme Part در پنل مدیریت

این ساختار به شما کمک می‌کند بخش‌های مختلف قالب را مستقل از یکدیگر توسعه دهید، در بخش‌های مختلف دوباره استفاده کنید و تنظیمات هر بخش را متناسب با نیاز وب‌سایت در اختیار مدیر قرار دهید.

> **توصیه:** توسعه و آزمایش Theme Part را در محیط توسعه (Development) انجام دهید و تغییرات را پس از بررسی و آماده‌سازی به محیط عملیاتی (Production) منتقل کنید.

## ۲. انتخاب Segment مناسب

هر Theme Part به یک **Segment** تعلق دارد. Segment نوع و کاربرد کلی Theme Part را مشخص می‌کند و تعیین می‌کند که آن بخش در کدام قسمت‌های قالب قابل استفاده باشد.

پوشه اصلی Segmentها در مسیر زیر قرار دارد:



```text
resources/views/segments
```

پیش از ساخت Theme Part، ابتدا کاربرد آن را مشخص کنید و سپس Segment متناسب با آن را انتخاب کنید.

### ۲.۲. الگوی انتخاب و نام‌گذاری Segment

یکی از نکات مهم در انتخاب Segment، تفاوت بین **نمایش مجموعه‌ای از محتوا در یک بخش از صفحه** و **نمایش یک صفحه مستقل برای فهرست محتوا** است.

در نام‌گذاری Segmentها، معمولاً الگوی زیر به کار می‌رود:

- نام مفرد، مانند `clip` یا `product`: نمایش یک محتوای مشخص
- نام جمع، مانند `clips` یا `products`: نمایش مجموعه‌ای از محتوا که می‌تواند در بخش‌های مختلف وب‌سایت استفاده شود
- نام جمع به همراه پسوند `_page`، مانند `clips_page` یا `products_page`: صفحه مستقل فهرست محتوا

برای مثال، اگر بخواهید آخرین کلیپ‌ها را در صفحه اصلی نمایش دهید، Segment مناسب معمولاً `clips` است؛ حتی اگر داده‌ها با یک Query سفارشی دریافت شوند.

اما اگر بخواهید صفحه‌ای مستقل برای نمایش آرشیو کلیپ‌ها ایجاد کنید، باید از Segment مربوط به `clips_page` استفاده کنید.

| نیاز | Segment پیشنهادی |
| --- | --- |
| نمایش یک کلیپ مشخص | `clip` |
| نمایش آخرین کلیپ‌ها در صفحه اصلی | `clips` |
| نمایش کلیپ‌های محبوب در یک بخش | `clips` |
| نمایش آرشیو کلیپ‌ها در صفحه مستقل | `clips_page` |
| نمایش یک محصول مشخص | `product` |
| نمایش محصولات پیشنهادی در یک بخش | `products` |
| نمایش فهرست اصلی محصولات | `products_page` |
| نمایش یک نوشته مشخص | `post` |
| نمایش آخرین نوشته‌ها در صفحه اصلی | `posts` |
| نمایش آرشیو نوشته‌ها | `posts_page` |

**نکته مهم:** Segment معمولاً کاربرد و محل استفاده Theme Part را مشخص می‌کند، نه Query یا روش دریافت اطلاعات آن را. بنابراین دو Theme Part با داده‌های متفاوت، مانند آخرین محصولات و محصولات پیشنهادی، می‌توانند هر دو در Segment `products` قرار بگیرند.

این الگو یک راهنمای نام‌گذاری است و باید با قراردادهای واقعی پروژه هماهنگ باشد.

### ۲.۳. آیا می‌توان Segment جدید ایجاد کرد؟

بله. در صورت نیاز می‌توانید Segment جدیدی ایجاد کنید؛ اما اضافه کردن یک پوشه به‌تنهایی کافی نیست.

باید محل‌های مجاز استفاده از Segment جدید را نیز در تنظیمات مربوط به `Area` تعریف کنید.

برای اطلاعات بیشتر، مستند زیر را مطالعه کنید: [area.md](models/area.md)

در این مستند، بخش `valid_segments` را بررسی کنید و Segment جدید را مطابق ساختار تعریف‌شده پروژه به فهرست مقادیر مجاز اضافه کنید.

پیش از ایجاد Segment جدید، بررسی کنید که آیا یکی از Segmentهای موجود نیاز شما را پوشش می‌دهد یا خیر. از ایجاد Segmentهای تکراری یا بیش از حد اختصاصی خودداری کنید، مگر اینکه تفاوت کاربردی مشخصی داشته باشند.

### ۲.۴. پوشه default-assets

پوشه `default-assets` برای نگهداری دارایی‌های پیش‌فرض مورد استفاده Theme Partها است و خودش یک Segment محسوب نمی‌شود.

هنگام توسعه، ساختار دارایی‌های موجود را بررسی کنید تا مشخص شود کدام فایل‌ها مشترک و کدام فایل‌ها اختصاصی هستند.

## ۳. ساخت Theme Part

پس از انتخاب Segment، یک نام مناسب برای Theme Part انتخاب کنید.

برای ایجاد Theme Part از دستور زیر استفاده کنید:



```bash
php artisan make:part {part} {segment}
```

پارامترهای دستور عبارت‌اند از:

- `part`: نام Theme Part
- `segment`: نام Segment موردنظر

برای مثال، برای ساخت یک بخش نمایش آخرین محصولات در Segment `index`، دستور زیر را اجرا کنید:



```bash
php artisan make:part LatestProducts index
```

در این مثال:

- `LatestProducts` نام Theme Part است.
- `index` Segment انتخاب‌شده است.

دستور، فایل‌های Theme Part را در پوشه مربوط به Segment انتخاب‌شده ایجاد می‌کند.

پس از اجرای موفق دستور، پنج فایل اصلی در اختیار خواهید داشت.

## ۴. ساختار فایل‌های Theme Part

| فایل | کاربرد |
| --- | --- |
| `PartName.php` | تعریف رفتار و چرخه حیات Theme Part |
| `PartName.blade.php` | تعریف ساختار HTML و نمایش محتوا |
| `PartName.scss` | تعریف استایل‌ها |
| `PartName.js` | تعریف رفتارهای تعاملی |
| `screenshot.webp` | تصویر پیش‌نمایش Theme Part |

در این جدول، `PartName` نام Theme Part است و باید با نام واقعی فایل‌ها جایگزین شود.

### پیشنهاد برای شروع توسعه

اگر طراحی موردنظر شما پیچیده است، بهتر است ابتدا ساختار ظاهری آن را آماده کنید و پس از نهایی شدن طراحی، کدهای HTML، استایل و JavaScript را به فایل‌های Theme Part منتقل کنید.

پیش از شروع توسعه از وجود Theme Part مشابه مطمئن شوید. اگر بخش مشابهی وجود دارد، معمولاً Duplicate کردن آن و اصلاح نسخه جدید سریع‌تر و سازگارتر با ساختار پروژه خواهد بود.

## ۵. فایل PHP؛ تعریف رفتار Theme Part

فایل PHP محل تعریف رفتار Theme Part و تعامل آن با تنظیمات و داده‌های سیستم است.

در این فایل می‌توانید تنظیمات موردنیاز را هنگام اضافه شدن Theme Part ایجاد کنید، داده‌های موردنیاز نمایش را آماده کنید و هنگام حذف آن منابع مرتبط را پاک‌سازی کنید.

نمونه زیر از ساختار موجود پروژه گرفته شده است:



```php
class MeloContact
{
    public static function onAdd(Part $part = null)
    {
        $setting = new Setting();
        $setting->section = 'theme';
        $setting->key = $part->area_name . '_' . $part->part;
        $setting->value = Group::first()->id;
        $setting->type = 'GROUP';
        $setting->size = 6;
        $setting->title = $part->area_name . ' ' . $part->part;
        $setting->save();

        $setting = new Setting();
        $setting->section = 'theme';
        $setting->key = $part->area_name . '_' . $part->part . '_title';
        $setting->value = __('Contact us');
        $setting->type = 'TEXT';
        $setting->size = 6;
        $setting->title = $part->area_name . ' ' . $part->part . ' title';
        $setting->save();
    }

    public static function onRemove(Part $part = null)
    {
        Setting::where(
            'key',
            $part->area_name . '_' . $part->part
        )->first()?->delete();

        Setting::where(
            'key',
            $part->area_name . '_' . $part->part . '_title'
        )->first()?->delete();
    }

    public static function onMount(Part $part = null)
    {
        return $part;
    }
}
```

در این نمونه، سه متد `onAdd`، `onRemove` و `onMount` استفاده شده‌اند.

### ۵.۱. متد onAdd

متد `onAdd` هنگام اضافه شدن Theme Part اجرا می‌شود و برای انجام عملیات اولیه آن کاربرد دارد.

یکی از کاربردهای اصلی این متد، ایجاد تنظیماتی است که مدیر وب‌سایت بتواند از طریق پنل مدیریت تغییر دهد.

در نمونه بالا، دو تنظیم ایجاد می‌شود.

**تنظیم اول: انتخاب گروه**



```php
$setting->key = $part->area_name . '_' . $part->part;
$setting->value = Group::first()->id;
$setting->type = 'GROUP';
```

این تنظیم برای انتخاب یک گروه استفاده می‌شود. مقدار اولیه آن شناسه اولین رکورد موجود در مدل `Group` است.

اگر هیچ گروهی در سیستم وجود نداشته باشد، عبارت `Group::first()->id` می‌تواند باعث خطا شود. در صورت امکان خالی بودن جدول گروه‌ها، باید این وضعیت را مدیریت کنید.

**تنظیم دوم: عنوان بخش**



```php
$setting->key = $part->area_name . '_' . $part->part . '_title';
$setting->value = __('Contact us');
$setting->type = 'TEXT';
```

این تنظیم یک مقدار متنی برای عنوان بخش ایجاد می‌کند. مقدار اولیه آن `Contact us` است و با استفاده از تابع ترجمه Laravel تعریف شده است.

ویژگی‌های `size` و `title` نیز اطلاعات مربوط به تنظیم را مشخص می‌کنند.

برای آشنایی با انواع تنظیمات قابل استفاده، مستند زیر را مطالعه کنید:

### ۵.۲. نام‌گذاری کلید تنظیمات

کلید هر تنظیم باید یکتا و قابل تشخیص باشد تا با تنظیمات سایر Theme Partها تداخل نداشته باشد.

در نمونه بالا، کلید تنظیم از ترکیب نام Area و نام Part ساخته شده است:



```php
$part->area_name . '_' . $part->part . '_title'
```

برای تعریف چند تنظیم در یک Theme Part، از پسوندهای معنادار استفاده کنید:



```php
$part->area_name . '_' . $part->part . '_title'
$part->area_name . '_' . $part->part . '_description'
$part->area_name . '_' . $part->part . '_limit'
```

این الگو خوانایی کد را افزایش می‌دهد و احتمال تداخل کلیدها را کاهش می‌دهد.

هنگام Clone کردن یک Theme Part، کلید تنظیمات را حتماً بررسی کنید؛ باقی ماندن کلیدهای نسخه اصلی ممکن است باعث شود دو بخش به یک تنظیم مشترک متصل شوند.

### ۵.۳. متد onMount

متد `onMount` برای اجرای عملیات موردنیاز هنگام بارگذاری یا آماده‌سازی Theme Part استفاده می‌شود. زمان دقیق فراخوانی آن به پیاده‌سازی داخلی xShop بستگی دارد.

در این بخش می‌توانید داده‌های موردنیاز برای نمایش را آماده کنید یا اطلاعات ورودی را تغییر دهید.

مثال:



```php
public static function onMount(Part $part = null)
{
    return $part;
}
```

این نمونه همان شیء `Part` را برمی‌گرداند و تغییری در آن ایجاد نمی‌کند.

اگر Theme Part به داده‌های محاسبه‌شده یا پردازش‌شده نیاز دارد، می‌توانید منطق مربوط به آن را در این بخش قرار دهید؛ مشروط بر اینکه با قرارداد فراخوانی متد در پروژه سازگار باشد.

**نکات عملکردی:**

- از اجرای Queryهای غیرضروری خودداری کنید.
- از پردازش‌های سنگین در هر بار بارگذاری صفحه پرهیز کنید.
- دریافت داده‌های متعدد را تا حد امکان بهینه کنید.
- منطق تجاری را تا حد امکان از قالب Blade جدا نگه دارید.

### ۵.۴. متد onRemove

متد `onRemove` هنگام حذف Theme Part برای پاک‌سازی منابع مرتبط با آن استفاده می‌شود.

برای مثال، اگر در `onAdd` تنظیماتی ایجاد کرده‌اید، در `onRemove` باید تنظیمات مربوط به همان Theme Part را حذف کنید.

در نمونه بالا، دو تنظیم ایجادشده حذف می‌شوند:



```php
Setting::where(
    'key',
    $part->area_name . '_' . $part->part
)->first()?->delete();
```

و:



```php
Setting::where(
    'key',
    $part->area_name . '_' . $part->part . '_title'
)->first()?->delete();
```

عملگر `?->` باعث می‌شود اگر رکوردی پیدا نشد، متد `delete()` روی مقدار `null` اجرا نشود.

**اصل مهم:** هر منبعی که هنگام اضافه شدن Theme Part ایجاد می‌کنید، باید در صورت نیاز هنگام حذف آن نیز پاک‌سازی شود.

### ۵.۵. چرخه حیات Theme Part

متدهای چرخه حیات باید مطابق قرارداد داخلی xShop تعریف شوند. پیش از تغییر نام متدها یا افزودن متد جدید، نحوه فراخوانی آن‌ها در هسته سیستم و Theme Partهای موجود را بررسی کنید.

## ۶. فایل Blade؛ ساختار و نمایش محتوا

فایل `PartName.blade.php` محل تعریف ساختار HTML و نمایش محتوای Theme Part است.

در این فایل می‌توانید از امکانات Blade، توابع کمکی پروژه و کامپوننت‌های Vue.js مورد پشتیبانی سیستم استفاده کنید.

Theme Part می‌تواند محتوای ایستا داشته باشد یا اطلاعات موردنیاز خود را به‌صورت پویا از سیستم دریافت کند.

### ۶.۱. نمونه نمایش آخرین محصولات

در مثال زیر، چهار محصول فعال و جدیدتر دریافت می‌شوند و هر محصول با استفاده از Theme Part مربوط به `product_grid` نمایش داده می‌شود.



```blade
<section
    class="LatestProducts live-setting"
    data-live="{{ $data->area_name . '_' . $data->part }}"
>
    {{-- استفاده از متغیرهای کمکی طراحی --}}
    <div class="{{ gfx()['container'] }}">
        <h1>
            {{ __('Latest products') }}
        </h1>

        <div class="row">
            {{-- دریافت محصولات از وب‌سایت --}}
            @foreach(
                \App\Models\Product::where('status', 1)
                    ->orderByDesc('id')
                    ->limit(4)
                    ->get() as $product
            )
                <div class="col-lg-3 col-md-6">
                    <div class="product-item">
                        {{-- استفاده از Theme Part پیش‌فرض کارت محصول --}}
                        @include(
                            \App\Models\Area::where('name', 'product-grid')
                                ->first()
                                ->defPart(),
                            compact('product')
                        )
                    </div>
                </div>
            @endforeach
        </div>

        <div class="p-4 text-center mt-2">
            {{-- استفاده از تابع کمکی آدرس محصولات --}}
            <a href="{{ productsUrl() }}" class="btn btn-secondary">
                {{ __('All products') }}
            </a>
        </div>
    </div>
</section>
```

### ۶.۲. توضیح اجزای نمونه

**کلاس****`live-setting`****و ویژگی****`data-live`**



```blade
<section
    class="LatestProducts live-setting"
    data-live="{{ $data->area_name . '_' . $data->part }}"
>
```

این دو مورد برای اتصال Theme Part به سازوکار ویرایش زنده استفاده می‌شوند.

کلاس `live-setting` به سیستم کمک می‌کند بخش موردنظر را شناسایی کند و ویژگی `data-live` شناسه مرتبط با تنظیمات آن بخش را مشخص می‌کند.

مقدار `data-live` در این نمونه از ترکیب نام Area و نام Part ساخته شده است.

هنگامی که مدیر وب‌سایت از طریق رابط ویرایش زنده، بخش موردنظر را انتخاب می‌کند، سیستم باید بتواند آن را به تنظیمات مربوط به همان Theme Part مرتبط کند.

> **نکته مهم:** کلاس `live-setting` و ویژگی `data-live` را بدون بررسی سازوکار داخلی سیستم حذف یا تغییر ندهید؛ این کار ممکن است عملکرد ویرایش زنده را مختل کند.

**استفاده از تابع****`gfx()`**



```blade
<div class="{{ gfx()['container'] }}">
```

این تابع برای دریافت کلاس‌های طراحی مورد استفاده پروژه به کار می‌رود و به هماهنگی ساختار بخش با سیستم طراحی کمک می‌کند.
مراجعه به مستندات: [استفاده از GFX](../02-consumer/10-gfx.md) و [model GFX](models/gfx.md)
**دریافت محصولات**



```php
\App\Models\Product::where('status', 1)
    ->orderByDesc('id')
    ->limit(4)
    ->get()
```

این Query محصولات فعال را بر اساس شناسه، از جدیدترین به قدیمی‌ترین مرتب می‌کند و حداکثر چهار محصول را دریافت می‌کند.

در پروژه واقعی، در صورت امکان منطق دریافت داده را از قالب جدا کنید تا نگهداری و بهینه‌سازی آن ساده‌تر باشد.

**استفاده مجدد از Theme Part دیگر**



```blade
@include(
    \App\Models\Area::where('name', 'product-grid')
        ->first()
        ->defPart(),
    compact('product')
)
```

در این بخش، Theme Part پیش‌فرض مربوط به نمایش کارت محصول پیدا شده و با ارسال متغیر `product` در قالب فعلی استفاده می‌شود.

این روش از تکرار کد جلوگیری می‌کند و امکان استفاده مجدد از اجزای طراحی موجود را فراهم می‌سازد.

توجه داشته باشید که وجود Area موردنظر و متغیرهای موردنیاز Theme Part مقصد باید تضمین شده باشد.

**لینک مشاهده تمام محصولات**



```blade
<a href="{{ productsUrl() }}" class="btn btn-secondary">
    {{ __('All products') }}
</a>
```

در این نمونه، تابع `productsUrl()` آدرس صفحه محصولات را برمی‌گرداند و تابع `__()` برای ترجمه متن استفاده می‌شود.

### ۶.۳. نکات مهم در توسعه Blade

- از نام‌گذاری مناسب برای کلاس‌های CSS استفاده کنید.
- تا حد امکان از توابع کمکی و اجزای مشترک پروژه استفاده کنید.
- متن‌های قابل مشاهده برای کاربر را با سازوکار ترجمه پروژه تعریف کنید.
- از تکرار Queryهای مشابه در یک صفحه خودداری کنید.
- هنگام استفاده از `first()`، وجود رکورد موردنظر را در نظر بگیرید.
- متغیرهای لازم برای `@include` را به‌صورت صریح ارسال کنید.
- ساختار HTML را با سیستم طراحی موجود هماهنگ نگه دارید.

## ۷. فایل SCSS؛ تعریف استایل‌ها

فایل `PartName.scss` برای تعریف استایل‌های اختصاصی Theme Part استفاده می‌شود.

در این فایل می‌توانید استایل‌های مربوط به ساختار HTML، فاصله‌ها، رنگ‌ها، تایپوگرافی، واکنش‌گرایی و حالت‌های تعاملی را تعریف کنید.

برای مثال:

scss

```
.LatestProducts {
    .product-item {
        height: 100%;
    }

    .product-title {
        margin-bottom: 0.75rem;
    }
}
```

این کد نمونه‌ای از ساختار SCSS است و باید با کلاس‌های واقعی قالب هماهنگ شود.

### ۷.۱. اصول پیشنهادی استایل‌نویسی

- استایل‌ها را تا حد امکان در محدوده کلاس اختصاصی Theme Part نگه دارید.
- از تغییر ناخواسته استایل عناصر عمومی وب‌سایت جلوگیری کنید.
- از متغیرها و ابزارهای طراحی تعریف‌شده در پروژه استفاده کنید.
- رفتار بخش را در اندازه‌های مختلف صفحه بررسی کنید.
- حالت‌های راست‌چین (RTL) و چپ‌چین (LTR) را در نظر بگیرید.
- پیش از تعریف متغیر جدید، وجود متغیر مشابه در پروژه را بررسی کنید.

## ۸. فایل JavaScript؛ افزودن رفتارهای تعاملی

فایل `PartName.js` برای افزودن رفتارهای تعاملی Theme Part استفاده می‌شود.

کد JavaScript این بخش باید مطابق سازوکار بارگذاری و اجرای اسکریپت‌ها در پروژه نوشته شود.

برای مثال:

javascript

```
window.addEventListener('load', function () {
    // کد موردنیاز Theme Part
});
```

این مثال نشان می‌دهد که کد داخل رویداد `load` اجرا می‌شود.

### ۸.۱. نکات مهم JavaScript

- از تعریف متغیرها و Event Listenerهای تکراری در صورت بارگذاری مجدد بخش جلوگیری کنید.
- اگر Theme Part در فرایند ویرایش زنده مجدداً رندر می‌شود، چرخه ایجاد و حذف Event Listenerها را بررسی کنید.
- وابستگی‌های JavaScript را مطابق استانداردهای پروژه مدیریت کنید.
- از دسترسی به عناصر DOM پیش از آماده شدن آن‌ها خودداری کنید.
- پس از تغییر JavaScript، مراحل ساخت دارایی‌های سمت کاربر را انجام دهید.

## ۹. فایل screenshot.webp؛ پیش‌نمایش Theme Part

فایل `screenshot.webp` تصویر پیش‌نمایش Theme Part است که در هنگام انتخاب یا مدیریت بخش‌های قالب به مدیر کمک می‌کند ظاهر آن را تشخیص دهد.

پس از تکمیل طراحی:

۱. از بخش طراحی‌شده یک تصویر مناسب تهیه کنید.

۲. تصویر را با نام `screenshot.webp` در محل مورد انتظار Theme Part قرار دهید.

۳. نمایش صحیح آن را در پنل مدیریت بررسی کنید.

تصویر پیش‌نمایش باید تا حد امکان نماینده ظاهر واقعی Theme Part باشد.

## ۱۰. استفاده مجدد و Clone کردن Theme Part

پیش از شروع توسعه، Theme Partهای موجود را بررسی کنید.

اگر Theme Part مشابهی وجود دارد، معمولاً بهتر است به‌جای شروع از صفر، پوشه آن را Duplicate کنید و نسخه جدید را مطابق نیاز خود تغییر دهید.

### ۱۰.۱. مراحل Clone کردن

۱. پوشه Theme Part مشابه را در Segment مربوطه Duplicate کنید.

۲. نام فایل‌ها و کلاس PHP را متناسب با Theme Part جدید تغییر دهید.

۳. کلید تنظیمات را بررسی و در صورت نیاز اصلاح کنید تا با نسخه اصلی تداخل نداشته باشد.

۴. فایل‌های Blade، SCSS و JavaScript را مطابق نیاز جدید تغییر دهید.

۵. تصویر پیش‌نمایش را به‌روزرسانی کنید.

۶. در صورت نیاز، Autoload کلاس‌های PHP را بازسازی کنید.

۷. دارایی‌های فرانت‌اند را طبق روال پروژه آماده کنید.

۸. Theme Part جدید را در محیط توسعه آزمایش کنید.

### ۱۰.۲. نکات مهم هنگام Clone کردن

- نام کلاس PHP باید با ساختار نام‌گذاری پروژه هماهنگ باشد.
- نام فایل‌ها و ارجاعات مرتبط را بررسی کنید.
- کلیدهای تنظیمات نسخه جدید نباید ناخواسته با نسخه اصلی مشترک باشند.
- وابستگی‌های غیرضروری را حذف کنید.
- عملکرد تنظیم زنده را بررسی کنید.
- در صورت تغییر نام یا ساختار کلاس‌ها، Autoload را به‌روزرسانی کنید.

## ۱۱. ساخت دارایی‌های فرانت‌اند و آماده‌سازی پروژه

### ۱۱.۱. دستور Client Asset Generator

برای جمع‌آوری و آماده‌سازی تغییرات فرانت‌اند از دستور زیر استفاده می‌شود:



```bash
php artisan client
```

این دستور برای آماده‌سازی دارایی‌های سمت کاربر در ساختار فعلی پروژه استفاده می‌شود و باید پیش از شروع کار با سامانه، حداقل یک بار اجرا شده باشد.

پس از تغییرات در Theme سایت نیز اجرای این دستور و انجام مراحل لازم برای ساخت دارایی‌ها (Assets Build) ضروری است.

> **توصیه:** اجرای این فرایندها را ترجیحاً در محیط توسعه انجام دهید و سپس خروجی تأییدشده را طبق فرایند استقرار پروژه به محیط عملیاتی منتقل کنید. هدف، تفکیک مراحل طراحی و آماده‌سازی از محیط اجرای Production است؛ نه اینکه این دستورات ذاتاً غیرقابل‌اعتماد باشند.

### ۱۱.۲. افزودن وابستگی‌های npm

اگر Theme Part شما به پکیج جدیدی از npm نیاز دارد، وابستگی را مطابق ساختار و رویه مدیریت پکیج‌های پروژه اضافه کنید.

پیش از نصب پکیج جدید، وابستگی‌های موجود را بررسی کنید تا از نصب چندباره کتابخانه‌های مشابه جلوگیری شود.

پس از افزودن وابستگی، مراحل لازم برای نصب و ساخت دارایی‌ها را مطابق رویه پروژه انجام دهید.

### ۱۱.۳. به‌روزرسانی Autoload در Composer

پس از افزودن Theme Part جدید و پیش از استفاده از آن در محیط مستقرشده، در صورت نیاز دستور زیر را اجرا کنید:



```bash
composer dump-autoload
```

این دستور اطلاعات Autoload کلاس‌های PHP را در Composer بازسازی می‌کند.

اجرای آن به‌تنهایی جایگزین سایر مراحل Build، پاک‌سازی Cache یا استقرار پروژه نیست؛ مراحل لازم را مطابق رویه انتشار xShop انجام دهید.

## ۱۲. نکات مهم هنگام توسعه

### ۱۲.۱. سازگاری RTL و LTR

Theme Part باید در هر دو حالت راست‌چین و چپ‌چین ظاهر و عملکرد مناسبی داشته باشد.

مواردی مانند جهت آیکون‌ها، فاصله‌ها، تراز متن، موقعیت عناصر و انیمیشن‌ها را در هر دو حالت بررسی کنید.

### ۱۲.۲. عملکرد و کارایی

- از Queryهای سنگین و غیرضروری در قالب خودداری کنید.
- تعداد درخواست‌های پایگاه داده را کنترل کنید.
- فایل‌های JavaScript و SCSS را تا حد امکان بهینه نگه دارید.
- تصاویر و منابع خارجی را با توجه به عملکرد صفحه مدیریت کنید.
- رفتار Theme Part را در صفحات مختلف بررسی کنید.

### ۱۲.۳. تنظیم زنده

هنگام توسعه Theme Part، ارتباط آن با سازوکار ویرایش زنده را حفظ کنید.

در صورت استفاده از الگوی موجود پروژه، کلاس `live-setting` و ویژگی `data-live` باید مطابق قرارداد سیستم تعریف شوند.

مقدار `data-live` در نمونه این مستند از ترکیب نام Area و نام Part ساخته می‌شود. هنگام Clone کردن، مقدار آن را متناسب با شناسه Theme Part جدید بررسی کنید.

### ۱۲.۴. بررسی نهایی

پس از تکمیل توسعه، موارد زیر را بررسی کنید:

- نمایش صحیح Theme Part در محل موردنظر
- صحت عملکرد تنظیمات در پنل مدیریت
- عملکرد ویرایش زنده
- صحت بارگذاری منابع موردنیاز
- سازگاری RTL و LTR
- عملکرد در اندازه‌های مختلف صفحه
- نبود خطا در Console مرورگر و گزارش‌های Laravel
- عدم تداخل با سایر Theme Partها
