# بازیابی گذرواژه 

روش‌های بازیابی گذرواژه :

- بازیابی متداول توسط email
- بازیابی با tinker
- بازیابی توسط مدیرت دیتابیس مثل phpmyadmin


## ۱. بازیابی از فرم «گذرواژه را فراموش کرده‌ام»

کاربر از صفحهٔ ورود روی لینک **«گذرواژه را فراموش کرده‌ام؟»** کلیک می‌کند، ایمیل حسابش را وارد می‌کند و لینک بازیابی را از طریق ایمیل دریافت می‌کند. با باز کردن لینک، می‌تواند گذرواژهٔ جدیدی تعیین کند.

این روش به شرطی کار می‌کند که تنظیمات ارسال ایمیل پروژه از قبل درست انجام شده باشد. اگر ایمیل بازیابی نمی‌رسد، تنظیمات ایمیل و لاگ‌های لاراول را بررسی کنید.

## ۲. بازیابی با Tinker

این روش برای مدیر یا توسعه‌دهنده‌ای است که به محیط اجرای پروژه دسترسی دارد. در ترمینال پروژه اجرا کنید:

```bash
php artisan tinker
```

سپس کاربر را با ایمیل پیدا کنید و گذرواژهٔ جدید را ذخیره کنید:

```php
$user = App\Models\User::where('email', 'user@example.com')->firstOrFail();

$user->password = Illuminate\Support\Facades\Hash::make('New-Strong-Password');
$user->save();
```

ایمیل را با ایمیل کاربر موردنظر و گذرواژه را با مقدار امن جایگزین کنید. گذرواژهٔ خام را در کد پروژه یا لاگ‌ها نگه ندارید.

## ۳. تغییر گذرواژه از طریق phpMyAdmin یا ابزار مدیریت دیتابیس

این روش زمانی کاربرد دارد که مدیر به دیتابیس دسترسی دارد، اما نمی‌تواند از Tinker استفاده کند. **گذرواژهٔ خام را مستقیماً در ستون `password` ننویسید**؛ مقدار آن باید هش‌شده باشد.

اگر PHP CLI روی سرور در دسترس است، می‌توان هش را بدون Tinker تولید کرد:

```bash
php -r "echo password_hash('New-Strong-Password', PASSWORD_BCRYPT), PHP_EOL;"
```

کپی کنید مقدار خروجی را در ستون `password` همان کاربر قرار دهید. نمونهٔ SQL، با فرض اینکه جدول `users` و شناسهٔ کاربر `123` است:

```sql
UPDATE users
SET password = 'PASTE_HASH_HERE'
WHERE id = 123;
```

در phpMyAdmin نیز همین کار را می‌توان با ویرایش ردیف کاربر انجام داد: هش تولیدشده را در ستون `password` قرار دهید و تغییرات را ذخیره کنید. نام جدول یا ستون ممکن است در پروژهٔ شما متفاوت باشد.

### نکات مهم

- روش ایمیلی، روش معمول برای بازیابی توسط خود کاربر است.
- Tinker و مدیریت دیتابیس را فقط مدیر یا پشتیبانی مجاز استفاده کند.
- هش را برای کاربر ارسال نکنید؛ فقط گذرواژهٔ جدید یا موقت را از مسیر امن در اختیارش بگذارید.
- پس از ورود با گذرواژهٔ موقت، از کاربر بخواهید آن را تغییر دهد.

**نکتهٔ دیباگ:** اگر کاربر پس از تغییر دیتابیس نمی‌تواند وارد شود، مطمئن شوید هش در ستون درست و برای حساب درست ثبت شده و روش هش پروژه با bcrypt سازگار است.
